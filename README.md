# Etavia (에타비아) — 시나리오 A

> 이름은 **ETA**(Estimated Time of Arrival, 예상 도착시각) + **via**(길·경유)에서 왔습니다.
> 이 앱이 하는 일 — "예상"과 "경유" — 이 그대로 이름입니다.
> (이전 이름: 들러 / Duler)

## 이 앱의 정체성

> **목적지 가는 길에 뭘 끼워 넣을 수 있는지, 한 문장으로 물으면 시간으로 답하는 앱.**

경로 앱이 아니라 **시간 타당성 판단기**입니다. 사용자의 질문은 "어떻게 가지?"가 아니라 "지금 들러도 9시까지 도착할 수 있나?"예요.

| 카카오맵 | Etavia |
|---|---|
| ① 지도에서 올리브영 검색 → ② 경유지 추가 → ③ 치킨집 또 검색 → ④ 또 추가 → ⑤ 순서 확인 | "올리브영이랑 치킨 들러서 숙소" **한 문장** |
| 체류시간 0분 가정 | **체류시간까지 계산**해 도착 시각을 답함 |

- **하지 않는 것**: 내비게이션, 앱 내 지도 (외부 지도 앱 연결로 대체)
- **해자**: 체류시간 데이터 + 그 목적까지 아는 문맥(할 일 개수·자연어) — 지도 앱이 못 갖는 신호
- **마감은 선택**: 기본은 `상관없어요`(예상 도착만). 마감을 정하면 여유·초과와 알림이 생김


“숙소 가기 전에 올리브영에서 화장품 사고 치킨 포장하고 싶어” 한 문장으로 경유지 순서를 계획하는 iOS 앱의 **시나리오 A 화면 구현체**입니다. 백엔드 없이 목 데이터와 `setTimeout` 지연만으로 화면·상호작용을 재현합니다.

원본 스펙: [design_handoff_scenario_a/README.md](design_handoff_scenario_a/README.md)

## 실행

```bash
npm install
npx expo start   # 터미널에서 i → iOS 시뮬레이터 (Expo Go)
```

- Expo SDK 57 · TypeScript · iOS 전용 · Expo Go에서 실행
- 지도는 Apple Maps(`react-native-maps` + `PROVIDER_DEFAULT`) — API 키 불필요

## 화면 흐름

```
A1 홈 → A2 자연어 입력+조건 → A3 계산 중 → A5 경로 3안 → A6 타임라인
                                   ↘ (실패 토글 시) A8 오류·재시도
A6에서: 할 일 칩 → A9 시트 · 매장 교체 칩 → A4 시트 · CTA → A7 지도 앱 시트
```

### 탭 내비게이션
- `계획/진행중/주변/더보기` 탭바가 모든 화면에 상주 (키보드 시 숨김). 탭 페이지끼리는 `replace` 전환, `계획` 탭은 보던 계획 화면으로 복귀 (`TabBar.tsx`)
- **더보기**: 유일하게 화면을 바꾸지 않고 **시트를 올린다** — `내 프로필`(화면 없음, `준비 중` 표시) · `이동 기록` · `설정`. 매일 쓰지 않는 것들을 여기 모아, 상시 노출되는 탭 자리는 실제로 매일 쓰는 것만 차지하게 했다. 현재 위치와 무관하게 언제든 다시 열린다 (다른 탭과 달리 `key === activeKey` 가드를 타지 않음)
- **진행중**: A5에서 경로를 확정하면(`planConfirmed`) 실행 뷰. 우측 상단 `편집` → A6 타임라인. 미확정이면 빈 상태 + 계획 만들기
  - **진행 중인 계획 카드가 맨 위**에서 좌측 파란 액센트 + elevated로 강조된다. (A6의 파란 *테두리*는 '드래그 가능'을 뜻하므로 시각 언어를 섞지 않았다.) 주행 상태 카드는 그 아래에 라벨 없이 — 카드 문구 자체가 제목이다
  - **일정 순서**: 좌측 커넥터 + 노드로 순서를 잇고, **장소마다 카드 한 장**(출발지·경유지들·목적지). 카드 사이에 `이동 12분 · 6.4km`
  - **커넥터·노드가 현재 위치를 말한다** — 지나온 구간은 **파란 실선**, 앞으로 갈 구간은 점선. 노드는 지나옴(회색 점) / 지금 여기(**이중 링**) / 예정(파란 점)
  - 이동 중이면 나는 두 노드 *사이*에 있으므로 `이동 중 · 12분 · 6.4km` 줄에 마커를 찍고, 거기까지만 실선을 긋는다. 체류 중이면 그 경유지 노드 자체가 이중 링이 된다 — **'나'는 언제나 이중 링, 장소는 점**
  - 커넥터는 부모가 통째로 그리지 않고 행마다 조각(`above`/`below`)으로 그린다. 그래야 구간별로 실선·점선을 달리 줄 수 있다 (`TimelineRow.tsx`)
  - 상태별 UI — `다음`(파란 배지 + elevated) / `체류 중`(초록 배지 + `남은 9분` + 도착·출발 시각) / `들렀어요`(취소선·흐림) / 예정(기본 카드)
  - **도착·출발은 GPS 지오펜스로만 자동 전환** (네이버 길찾기 방식). 경유지 반경 안에 들어오면 도착, 벗어나면 출발. 들어올 때와 나갈 때 반경을 달리 둬 경계에서 깜빡이지 않음 — 실제 GPS 150/250m, 시뮬레이션 400/600m
  - **수동 버튼 없음.** 카드에는 `가까워지면 자동으로 도착 처리돼요` 안내만 표시
  - 상태는 `passedCount` + `atStop`으로 관리
- **확정 시 내비게이션**: A5의 `N분 경로로 계속` → 스택을 `[Home, Today]`로 리셋. 진행중으로 넘어가고 **계획 탭은 초기 화면(A1)** 이 되어 곧바로 새 경로를 만들 수 있음 (진행 중 계획이 있으면 `오늘 계획을 바꿀까요?` 확인)
- 확정된 계획이 있는 상태에서 홈의 `계획 만들기`를 누르면 **"오늘 계획을 바꿀까요?"** 확인 시트 (새로 계획하기 / 진행 중인 계획 보기)
- **이동 기록**: 더보기 시트에서 진입. 이동 건별 카드 → 지난 계획 상세 시트(읽기 전용 타임라인). `이 경로로 다시 계획하기` → 목적지 채워진 홈
- **주변**: `예상 혼잡도` → `한줄 소식` → `제보 입력` 세 덩어리
  - **체류시간 수동 입력(`여기 얼마나 걸렸어요?`) 카드는 제거했다.** 도착·출발을 GPS로 감지하므로 체류시간은 이미 자동으로 계산된다 — 같은 걸 두 번 물으면 그 화면 전체가 번거로워진다. 기능이 사라진 게 아니라 UI만 뺀 것
  - **진행 중 계획과 위치 매핑**: 확정된 계획이 있으면 다음 경유지에 도착한 것으로 보고(목) 제보 위치가 자동 선택됨. **제보는 지금 있는 장소에서만 가능** — 도착한 경유지·현재 지역 칩만 선택 가능하고 아직 안 간 경유지는 비활성(45% 흐림)
  - **내 제보 수정**: 내가 쓴 글 우측 연필 아이콘 → 입력창에 글이 실리고 `내 제보 수정 중` 배너(취소 포함) 표시 → 전송 시 `수정됨` 메타로 갱신
  - 혼잡도 제보는 여유/보통/혼잡/매우혼잡 4단계, 가운데 정렬. 대상 장소(도착한 경유지 또는 `평창 일대`) + 상태 큰 글씨 + `최근 1시간 제보 N건 기준` 캡션이 한 줄. 장소 단위 제보가 0건이면 `제보 없음` 빈 상태(`첫 제보를 남겨주세요`)를 보여주고, 내 제보가 첫 건이 되면 그 레벨·1건으로 갱신
  - **한줄 소식은 내 경로 관련만, 방문 순서 정렬**: 소식마다 경유지 앵커를 갖고, 계획 확정 시 앵커가 내 경유지와 일치하는 소식만 `구간 도로 → 경유지` 순으로 정렬 (`내 경로 순`). 매장을 교체하면 이전 매장 소식은 자동으로 빠짐. 미확정이면 전체 최신순
- **설정**: 하단 **더보기** 시트에서 진입 (push + back). 홈 우측 상단의 톱니 아이콘은 제거 — 첫 화면은 "어디로 가는가"만 묻는다

### 개발용 진입점
- **개발 메뉴**: `더보기` → `설정` → `개발 메뉴` 행, 또는 A1 타이틀 **길게 누르기** → 데이터셋 3종 전환 + `다음 계산 실패(A8)` 토글
- **A8 바로가기**: A6 헤더의 `편집` **길게 누르기**

## 동작하는 것

| 항목 | 구현 |
|---|---|
| A1 계획 조건 입력 | 출발지는 **실제 GPS + 역지오코딩**(`내 위치` + 주소). 목적지는 카드 행 탭 → **검색 시트**(이름·주소·거리, 250ms 디바운스, 가까운 순 정렬) · 이동수단 세그먼트 · 도착 목표 시각(30분 단위 select 시트). 하단은 파란 `계획 만들기` 버튼(가짜 입력창 대체). 목적지 미지정이면 목적지 시트가 먼저 열림 |
| A2 채팅 전용 | 계산 조건은 A1로 이동. 헤더에 `자동차 · 오늘 21:00까지 도착` 요약 한 줄. 채팅 첫머리에 어시스턴트 예시 버블("이렇게 말해보세요") — A1의 예시 섹션을 흡수 |
| A3 진행률 | 6초 ease-out 애니메이션 + 체크리스트 단계 전환 → 자동 A5 (실패 플래그 시 A8) |
| A5 3안 선택 | 카드 탭 → 선택 카드가 확장형(배지+점선 커넥터)으로 전환, CTA로 A6 확정 |
| 동작 없는 헤더 액션 제거 | A2 `요약`·A5 `정렬`은 스펙에 있었지만 붙일 동작이 없어 제거. 누를 수 있어 보이는데 아무 일도 없으면 나머지 화면도 못 믿게 된다 |
| A5 경유 매장 변경 | 확장 카드의 경유지 칩(`올리브영 ▾`, `교촌치킨 ▾`) 탭 → A4 후보 시트(현재 경로 배지 표시) → 브랜드 선택 시 그 안(案)의 총시간·직행 대비 즉시 갱신, CTA 확정 시 A6에 반영 (`optionOverrides`) |
| A6 드래그 재정렬 | 장소마다 카드 한 장 + 좌측 커넥터(진행중 탭과 동일한 구조). **카드 전체를 길게 눌러** 순서 변경 — 햄버거 핸들 없음. 드롭 후 0.6초 목 재계산 |
| A6 스와이프 삭제 | gesture-handler `ReanimatedSwipeable`, 삭제 후 재계산 |
| A6 `할 일 1/3` → A9 | 체크박스 탭으로 완료 토글, **할 일 텍스트 탭으로 인라인 수정**, `할 일 추가`로 새 항목 생성(빈 내용으로 확정하면 삭제). 변경은 A6 칩 카운트에 즉시 반영. **체크는 재계산을 유발하지 않음** |
| 출발 5분 전 알림 | 경유지에 도착하면(A9 진입) **자동 예약** — 별도 토글 없음. 알림에 여유/보통/혼잡/매우혼잡 액션이 붙어 잠금화면에서 바로 혼잡도 제보 (목: 6초 뒤 발송) |
| A6 `매장 교체` → A4 | 정렬 세그먼트(추가시간/영업 상태/거리) 실제 정렬. **후보를 탭하면 목록에서 그 자리 그대로 펼쳐진다**(4열 지표 + `이 매장으로 정하기`) — 펼친 후보를 위로 끌어올리지 않는다. 자리가 바뀌면 내가 고른 건지 골라야 하는 건지 헷갈린다. 확정하면 경로 반영 후 시트가 닫힘. `추천`·`현재 경로` 배지는 접힌 행에도 그대로 보임 |
| A6 = 경로 편집 화면 | 진행중 탭의 `편집`으로 진입. 헤더 우측은 `완료`(뒤로), 하단 CTA는 **`AI와 대화로 수정하기`** → A2. 실행용 `지도 앱에서 열기`는 진행중 탭에만 둠 — 편집과 실행의 역할을 분리 |
| A6 요약 위치 | `총 예상 / 경유지 / 직행 대비`(+마감 여유)를 **헤더로 이동**. 하단은 폰을 쥔 손가락에 가려지는 영역이라 읽어야 하는 정보를 두지 않음. 하단엔 CTA만 |
| A6 조작 안내 | 하단 힌트 문구는 경유지가 많으면 화면 밖으로 밀려나 제거. 대신 **이동 가능한 카드에 파란 테두리**(1.5pt)로 상시 표시하고, 최초 진입 시 **2페이지 스포트라이트 가이드**(`SpotlightGuide`)로 드래그 재정렬과 AI 대화 수정을 각각 포커스해 설명. 앱 실행당 1회 |
| 탭바 아이콘 | 사각형·원 자리표시를 실제 아이콘으로 교체 — 계획(경로 노드), 진행중(재생), 기록(시계), 주변(위치 핀). `react-native-svg`로 직접 그림 |

## 위치 추적 (실제 GPS)

`expo-location`으로 실제 GPS를 받아 도착·출발·이탈을 판정합니다. 위치 공급원은 둘이고 **판정 로직은 하나를 공유**합니다.

| 공급원 | 설명 |
|---|---|
| `live` | 실제 GPS. **경로를 확정하면 자동으로 시작** (권한 요청 → 즉시 1회 측정 → 20m마다 구독) |
| `driving` / `deviate` / `stuck` | 개발 메뉴의 가상 주행 |

- 권한은 `NSLocationWhenInUseUsageDescription`(앱 사용 중)만 씁니다. 백그라운드 위치는 요구하지 않아 승인 장벽이 낮습니다
- 거부되면 추적을 끄고 개발 메뉴에 사유를 표시합니다
- **경로에서 5km 이상 떨어지면** 이탈 판정을 돌리지 않고 `경로에서 떨어진 위치예요` 상태로 둡니다 (다른 지역에 있는 경우)
- 목 경로가 평창 좌표라 다른 지역에서는 검증이 안 되므로, 개발 메뉴의 **`목 경로를 내 위치로 옮기기`**로 경로 전체를 현재 위치로 평행이동해 실제 GPS 동작을 확인할 수 있습니다

## 출발지·목적지 입력

**출발지에는 검색 UI가 없습니다.** 좌표는 GPS가 이미 알고 있고 경로 계산도 좌표로 하므로, 텍스트로 바꿀 필요 자체가 없습니다. 주소는 오직 사람이 읽으라고 `reverseGeocodeAsync`로 만들어 부제로 깝니다 (iOS 내장 지오코더라 API 키 불필요). 상호명은 일부러 만들지 않습니다 — 반경 안에 POI가 수십 개라 좌표만으로는 특정이 불가능하고, 그래서 지도 앱들도 출발지에 `내 위치`라고만 씁니다.

| 상태 | 표시 |
|---|---|
| 정상 | `내 위치` + 역지오코딩 주소, 헤더에 `현재 위치 <시/군/구>` |
| 권한 거부 | `위치 권한이 필요해요` + 안내. 거리 표시도 생략 |
| 실패 | 눌러서 재시도 |

주소 조립은 국가별로 순서가 다릅니다 — 한국(`isoCountryCode === 'KR'`)은 큰 단위부터(`시도 시군구 읍면동 도로명 번지`), 그 외는 번지부터. 특별시·광역시는 `region`과 `city`가 같은 값으로 와서 중복을 제거합니다.

**검색이 필요한 건 최종 목적지 하나뿐입니다.** 경유지는 "치킨집 들러야 해"처럼 말로 던지면 AI가 경로상에서 찾아주는 게 이 앱의 방식이라 검색창이 없습니다. 목적지 검색도 지도를 그리지 않습니다 — 이름·주소·현재 위치로부터의 거리만 리스트로 보여주면 충분하고, 핀을 찍기 시작하면 정체성이 흐려집니다.

### 검색 제공자 추상화 (`src/lib/places.ts`)

분기 기준은 **사용자 국적이 아니라 검색 대상 좌표**입니다. 한국에 있으면서 나리타공항을 찍을 수 있으니까요.

| 제공자 | 클라이언트 직접 호출 | 비고 |
|---|---|---|
| 카카오 로컬 | 가능 (REST 키) | 좌표가 WGS84 그대로. 국내는 이쪽이 붙이기 쉬움 |
| Google Places | 가능 | 결제수단 등록 필요 |
| 네이버 | **불가** | 시크릿 헤더가 필요해 서버를 하나 둬야 함. 좌표도 TM128이라 변환 필요 |

**카카오·구글 모두 실제로 연동돼 있습니다.** `regionProviderKey(near)`로 현재 위치가 국내면 카카오, 해외면 구글을 씁니다.

| | 엔드포인트 | 키 |
|---|---|---|
| 카카오 | `GET dapi.kakao.com/v2/local/search/keyword.json`, `Authorization: KakaoAK` | `app.json`의 `extra.kakaoRestKey` |
| 구글 | `POST places.googleapis.com/v1/places:searchText`, `X-Goog-Api-Key` + `X-Goog-FieldMask` | `extra.googlePlacesKey` |

- 국내 POI는 카카오가 더 촘촘하고(지점명·상호), 해외는 카카오가 사실상 비어 있습니다
- **해외에서 한국 장소를 찾는 경우도 막히지 않습니다** — 구글이 한국을 커버하므로
- 카카오에는 국내 좌표일 때만 `x`/`y`+`sort=distance`를 넘깁니다. 해외 좌표를 기준으로 거리순 정렬해봐야 의미가 없습니다
- **원하는 쪽 키가 없으면 있는 쪽이라도 쓰고**, 둘 다 없으면 조용히 목 카탈로그로 떨어집니다. 키 없이도 화면은 그대로 동작해야 합니다
- 실패하면 빈 목록이 아니라 `검색에 실패했어요 · 연결 상태나 API 키를 확인해 주세요`를 띄웁니다 — 원인 모를 빈 화면이 제일 나쁩니다

**키는 앱 번들에 들어가므로 추출이 가능합니다.** 카카오는 이 방식을 허용하지만, 실서비스로 가면 프록시 서버를 두는 게 맞습니다. Admin 키는 절대 넣으면 안 됩니다.

목 카탈로그는 키가 없을 때의 폴백으로 남겨뒀습니다. 주소는 실제 도로명 대신 행정구역 수준으로만 적었습니다 — 목 데이터가 정확한 척하면 실제 응답과 섞였을 때 구분이 안 됩니다.

검색으로 못 찾는 곳도 있으므로 `입력한 대로 설정` 행으로 임의 문자열을 그대로 쓰는 길을 항상 남겨둡니다 (이 경우 좌표는 `null`).

## 외부 지도 앱 연동 (A7)

`src/lib/mapLinks.ts`의 파라미터는 목이 아니라 각 앱의 **공식 URL scheme 스펙**입니다.

| 앱 | 형식 | 경유지 | 이동수단 |
|---|---|---|---|
| 네이버지도 | `nmap://route/{car\|walk\|public}` | `v1`~`v5` (5개) | 경로 path |
| 카카오맵 | `kakaomap://route` | `vp`~`vp5` (5개) | `by=car\|foot\|publictransit` |
| Google Maps | `https://www.google.com/maps/dir/?api=1` (universal link) | `waypoints` 9개 | `travelmode=driving\|walking\|transit` |

- 네이버는 `appname`(번들 ID)이 **필수**입니다
- Google은 커스텀 스킴(`comgooglemaps://`)이 아니라 universal link를 씁니다. 앱이 설치돼 있으면 앱이 가로채고, 아니면 브라우저로 떨어지는데 **브라우저에서는 경유지가 3개로 줄어듭니다**
- 설치 여부 판정(`canOpenURL`)은 `app.json`의 `LSApplicationQueriesSchemes`에 스킴이 등록돼야 동작합니다. **전부 미설치로 나오면 그 판정을 통째로 무시**합니다 — 지도 앱이 하나도 없는 기기보다 등록이 빠진 빌드(Expo Go 포함)일 확률이 훨씬 높습니다
- 미설치로 보여도 일단 열어보고, **확실히 미설치일 때만** 스토어로 넘깁니다

### 카카오내비를 뺀 이유

순수 URL scheme이 없습니다. 공식 문서상 `NaviApi.shared.navigateUrl()`로 **SDK가 URL을 만들어야 하고**, 네이티브 앱키 발급과 SDK 설치가 전제입니다(`LSApplicationQueriesSchemes` 값도 `kakaonavi`가 아니라 `kakaonavi-sdk`). 카카오맵으로 넘기면 거기서 내비를 띄울 수 있어 SDK를 들일 이득이 없다고 판단했습니다.

### 대중교통 — 구간 단위 핸드오프

**대중교통은 세 앱 모두 경유지를 받지 않습니다.** 앱들의 한계가 아니라 대중교통 경로의 구조 때문입니다 — 자동차는 A→B→C가 하나의 연속된 선이지만, 대중교통은 구간마다 별개의 환승 계획이라 하나로 묶어 안내하는 개념이 없습니다. 웹 링크로도 우회할 수 없습니다.

그래서 전체를 한 번에 넘기는 대신 **"지금 갈 구간"만** 넘깁니다.

- 어디까지 왔는지는 앱이 압니다(`passedCount`·`atStop`) → 다음 구간이 자동으로 골라져 있음
- 구간 하나는 1:1이라 세 앱 모두 완벽히 지원
- 경유지에 도착하면 GPS가 자동 감지 → 다음 구간이 알아서 갱신
- 지금 갈 구간의 출발지는 계획상 좌표가 아니라 **실제 GPS 위치**를 씁니다
- 대중교통은 '지금 출발' 기준 시간표가 중요해서, 나중 구간을 미리 열어봐야 어차피 의미가 없습니다

UI도 그에 맞춰 바뀝니다 — 진행중 탭 CTA가 `다음 구간 길찾기`가 되고, A1에서 대중교통을 고르는 **순간** 이 동작을 미리 안내합니다. 뒤늦게 알면 배신감이 듭니다.

**아직 없는 것**: 배차 간격과 막차. "여기서 15분 머물면 다음 버스는 20분 뒤"는 자동차의 `+15분`과 완전히 다른 계산인데, 지금 목 데이터에는 없습니다.

## 알려진 경고
- `ref.measureLayout must be called with a ref to a native component` — `react-native-draggable-flatlist` 4.0.3이 RN 신아키텍처(Fabric)에서 내는 경고입니다. 드래그 동작에는 영향이 없는 것으로 알려져 있으며, 라이브러리 지시가 스펙에 있어 유지했습니다.
- 검증 편의를 위해 딥링크(`etavia://` / `exp://<host>/--/<screen>`)로 각 화면에 직접 진입할 수 있습니다: `home` `plan` `calculating` `options` `timeline` `error`, 그리고 `timeline?sheet=task|candidate|mapapp`, `options?pick=1`(매장 선택 시트).
