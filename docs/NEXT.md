## 지금 어디까지 왔나

### 앱 (동작함)

- **시간 타당성 판단** — 들렀다 가도 목표 시각에 도착하나. 지도는 그리지 않는다
- **배경 위치 추적** — `expo-task-manager`. 포그라운드 전용이던 걸 고쳐서 주행 중 경유지 전환이 잡힌다. **'항상 허용' 권한 필수**
- **도착 알림** — 경유지 도착·출발, 최종 목적지 도착(마감 대비 결과 포함)
- **장소 검색** — 국내 카카오 / 해외 구글. 키는 `.env`(gitignored) → `app.config.js`
- **지도 앱 핸드오프** — 네이버·카카오맵·구글. 경유지 5개 초과 시 앱별로 생략 개수를 알린다
- **혼잡도 제보** — 경유지 도착 시에만. 화면·리듀서 양쪽에서 막는다
- **채팅 → 경유지 칩** — 추출 결과를 칩으로 드러내고 지울 수 있다

### 서버 (뼈대만, 미배포)

`server/` — Cloudflare Workers. 키를 가리고 LLM 응답을 검증해 넘기는 얇은 프록시.
경로 계산·시간 판정은 앱에 남는다.

- `src/index.ts` — `/extract` 엔드포인트. 앱 토큰 + 기기당 분당 10회
- `src/schema.ts` — **인젝션의 실제 방어선.** LLM이 무엇을 뱉든 이 스키마를 통과해야 앱에 닿는다
- `src/prompt.ts` — 시스템 프롬프트(원본은 `prompts/extract-intent.md`)

### 2. Workers 배포

```bash
cd server && npm i
npx wrangler kv namespace create RATE     # id를 wrangler.toml에
npx wrangler secret put OPENAI_API_KEY
npx wrangler secret put APP_TOKEN
npx wrangler secret put KAKAO_MOBILITY_KEY  # developers.kakaomobility.com 키. 카카오 로컬 키와 별개
npx wrangler dev                          # 로컬에서 147개 돌려 기준선과 비교
npx wrangler deploy
```

앱 `.env`에 `SERVER_URL=https://…workers.dev`, `APP_TOKEN=…`을 넣으면 `app.config.js`가 extra로 올린다.

**`/route`(2026-09-11 추가)** — 카카오모빌리티 자동차 길찾기 프록시. 경유지 ≤ 5, 미래운행(departAt).
앱은 `serverRouteProvider`로 부른다. 쿼터는 자동차 **일 10,000건 무료, 초과 8원/건**, 미래운행 일 5,000건
(요금표 developers.kakaomobility.com/price). 계획당 5~9회니 하루 1,000건 남짓 무료. 다중 목적지(일 1,000건
무료, 초과 20원)도 요금표에 있어 제휴 없이 될 수 있다 — V=1에 쓰면 2회로 끝난다. 나중에 확인.

그 다음 `src/lib/intent.ts`가 서버를 보게 바꾼다. **실패하면 로컬 목으로 떨어지게** —
서버가 죽어도 계획은 세워져야 한다.

### 3. 최적 경로 계산 — 설계 확정, 구현 대기

2026-09-11 Codex 두 라운드 검토를 거쳐 `docs/최적경로-설계.md`로 정리했다.
아래 v1 아이디어("좁히고 재기")는 유지하되 전제가 바뀌었다:

- **행렬 API는 없다.** 카카오 다중목적지·Matrix는 제휴 승인 대상이고 Google Matrix는 요소당 과금.
  실측은 "직행 1 + 전체 경로 R회"뿐이고, 응답의 section별 시간을 **재사용**해 나머지 조합을 재채점한다.
- V=1은 후보 8개 전부 실측(9회). V≥2는 R=4 + 조건부 2라운드(+2~3). 합계 5~8회.
- 추정으로 후보를 **삭제하지 않는다.** 추정치는 하한이 아니다.
- 3안 다양성은 실측 후 Jaccard 패널티로. "경유지 뺀 안"은 옵션이 아니라 조건 완화안.
- 대중교통은 1안만 순차 실측. 3초 안에 3안은 무리.
- 구현 전 확인: 카카오모빌리티 일반 키 일일 무료 쿼터.

구현 순서는 설계 문서 끝에 있다. 1단계는 `src/lib/routePlan/` 순수 모듈 + 목 공급자 + `node --test`.

**2026-09-11 구현 상태:** 1·1.5단계 완료 — `src/lib/routePlan/`(plan·corridor·enumerate·legs·score·select·mockProvider)과
`src/lib/corridorSearch.ts`. `npm test`로 목 공급자 기준 전 단계가 돈다. 아직 UI·서버에 연결 안 됨.
2단계(Workers `/route`, `serverRouteProvider`)도 완료. 배포는 아직. 다음: `OptionsScreen`·`CandidateSheet`·`plan.tsx` 연결.

## LLM 실측에서 드러난 것

**`endpoints`를 4건 전부 놓쳤다.** 스키마엔 있는데 프롬프트가 시키지 못했다.
`회사 말고 집으로 가자`가 `dest=null`로 나왔다. 프롬프트에 예시 3개를 박아 넣었고,
**재실행으로 확인해야 한다** (`node server/run-llm.mjs`).

**비결정성이 실측됐다.** `구시까지 도착`이 36건 테스트에선 09:00, 147건에선 null.
같은 입력에 다른 답이다. `temperature=0`으로 낮췄지만 근본 해결은 아니다.
**실질 방어는 칩 UI** — 사용자가 뭘 알아들었는지 보고 고칠 수 있으면 비결정성이
치명상이 되지 않는다.

## 보강(/enrich) — 2026-09-13 실측과 이월 항목

**실측 지연 (콜드, 배포된 Worker 기준)**

| 네이버 블로그 조회 | 시간 |
|---|---|
| 1곳 | 1.7초 |
| 6곳 | 1.7초 |
| 12곳 | 3.4초 |
| `/route` 1회 | 3.1초 |

동시 연결 한도가 6이라 7곳부터 회차가 나뉜다. **6곳이 한 회차에 들어가는 최대치다.**
그래서 블로그 조회를 6곳으로 잡았다(`BLOG_LOOKUP_MAX`). 후보 30곳 중 6곳이다.

**이월 — 큰 것부터**

- **30곳을 다 덮으려면 질의 방식을 바꿔야 한다.** 장소마다 묻는 대신 '지역+업종'으로
  2~3번 묻고 블로그 글 제목을 후보명과 맞춘다(entity matching). 호출 수가 후보 수와
  무관해지므로 한 회차에 30곳을 덮는다. 지금 방식으론 6곳이 천장이다.
- **블로그 캐시 stale 재사용.** 지금은 24시간이 지나면 미조회 취급이다. fresh 24시간 /
  stale 14일로 나눠, stale 값은 순위에 쓰고 백그라운드로 갱신하면 콜드가 거의 사라진다.
  설계 §2.1.1의 "24시간을 넘기지 않는다"를 바꾸는 일이라 사양 수정이 먼저다.
- **플래너 예약 3.5초는 측정값이 아니라 근사다.** `/route` 1회가 3.1초인 걸로 잡았다.
  플래너 실측 p95를 재서 `PLANNER_RESERVE_MS`를 교체해야 한다. 이 값이 보강 예산을
  직접 깎으므로, 과대하면 보강이 굶고 과소하면 계획이 타임아웃된다.
- **예산 카운터를 Durable Object로.** KV는 read-modify-write가 원자적이지 않고 읽기가
  eventual consistency다. 실측에서 카운터가 64→56으로 되돌아가는 걸 봤다(옛 값을 읽고
  덮어씀). 앱이 슬롯을 순차로 불러도 다른 사용자의 동시 요청까지는 못 막는다.
  Durable Object로 옮기기 전까지 슬롯 병렬화는 금지다.
- **`/enrich-batch`로 슬롯 통합.** 슬롯마다 따로 부르니 슬롯 수만큼 지연이 쌓인다.
  한 요청에 모든 슬롯을 담으면 캐시 조회·예산 예약·외부 호출을 한 번에 묶을 수 있다.
  Durable Object 예산 게이트가 선행 조건이다.
- **구글 일일 할당량 40을 무료 체험판 졸업 직후 걸어야 한다.** 지금 코드의 월 900회
  카운터가 유일한 방어선이다.
- **구글 `hours`를 받아오지만 안 쓴다.** 자동 스왑에 쓰려면 닫힌 매장 걸러내기가 같이 필요하다.
- **비동기 보강은 이번 계획의 품질을 못 올린다.** 다음 요청용 캐시 예열일 뿐이고,
  확정된 경유지가 뒤늦게 바뀌는 race·UI 튐이 생긴다. 하려면 planId·inputHash로 늦은
