## 지금 어디까지 왔나

### 앱 (동작함)

- **시간 타당성 판단** — 들렀다 가도 목표 시각에 도착하나. 지도는 그리지 않는다
- **배경 위치 추적** — `expo-task-manager`. 포그라운드 전용이던 걸 고쳐서 주행 중 경유지 전환이 잡힌다. **'항상 허용' 권한 필수**
- **도착 알림** — 경유지 도착·출발, 최종 목적지 도착(마감 대비 결과 포함)
- **장소 검색** — 국내 카카오 / 해외 구글. 키는 `.env`(gitignored) → `app.config.js`
- **지도 앱 핸드오프** — 네이버·카카오맵·구글. 경유지 5개 초과 시 앱별로 생략 개수를 알린다
- **혼잡도 제보** — 경유지 도착 시에만. 화면·리듀서 양쪽에서 막는다
- **채팅 → 경유지 칩** — 추출 결과를 칩으로 드러내고 지울 수 있다

### 서버 (뼈대만, 미배포)

`server/` — Cloudflare Workers. 키를 가리고 LLM 응답을 검증해 넘기는 얇은 프록시.
경로 계산·시간 판정은 앱에 남는다.

- `src/index.ts` — `/extract` 엔드포인트. 앱 토큰 + 기기당 분당 10회
- `src/schema.ts` — **인젝션의 실제 방어선.** LLM이 무엇을 뱉든 이 스키마를 통과해야 앱에 닿는다
- `src/prompt.ts` — 시스템 프롬프트(원본은 `prompts/extract-intent.md`)

## 다음 작업

### 1. 모델 — gpt-5.6-sol로 결정됨

여러 모델 비교는 하지 않기로 했다(ChatGPT 계정은 설정된 모델만 허용해서
`gpt-5.3-codex`·`gpt-5.1` 모두 400이었고, 굳이 비교할 필요 없다는 판단).

`server/src/index.ts`의 `DEFAULT_MODEL`이 `gpt-5.6-sol`이고 `OPENAI_MODEL`
secret으로 덮을 수 있다. **Codex CLI(ChatGPT 계정)에서 쓰는 이름과 API에서
쓰는 이름이 다를 수 있으니 배포 전에 확인할 것.**

**전체 147건 실측 기준선(2026-09-10):**

| | 통과 | 실패 | 미검증 | 무응답 |
|---|---|---|---|---|
| 로컬 목 | 128 | 17 | 2 | — |
| gpt-5.6-sol | **133** | 12 | 2 | **0** |

101K 토큰(40건씩 4배치). `node server/run-llm.mjs`로 재현·재실행.

**예상 비용은 무시해도 될 수준이다.** 추출 1건 ≈ 810토큰(시스템 600 + 입력 60 + 출력 150).
`gpt-4o-mini` 기준 **1건 0.0002달러**, 1000건 300원. 프롬프트 캐싱을 켜면 더 낮아진다.
진짜 비용은 LLM이 아니라 라우팅 API다.

### 2. Workers 배포

```bash

npx wrangler secret put OPENAI_API_KEY
npx wrangler secret put APP_TOKEN

```

그 다음 `src/lib/intent.ts`가 서버를 보게 바꾼다. **실패하면 로컬 목으로 떨어지게** —
서버가 죽어도 계획은 세워져야 한다.

### 3. 최적 경로 계산 — 좁히고 재는 2단계

경유지 N개 × 후보 3곳이면 조합이 `3^N × N!`. N=3에 162가지라 전부 API로 재면 요금이 난다.

**1단계 · 좁히기(API 0회)** — 출발-목적지 직선에서 수직거리가 먼 후보를 버린다. 162 → 6~12가지.
**2단계 · 재기(API N회)** — 살아남은 조합만 실제 라우팅으로.

순서 최적화는 규모로 갈린다:

| 경유지 | 방법 | 호출 |
|---|---|---|
| ~4개 | 순열마다 전체 경로 1회 | 최대 24 |
| 5개+ | 쌍별 시간 행렬 + 로컬 브루트포스 | (N+2)² |

교차점이 4개쯤. 지금은 5개 이하가 대부분이니 **순열 방식이 단순하고 싸다**.

### 4. 사용자 대화 이력 축적 → 정기 분석

사용자가 실제로 뭐라고 치는지가 케이스보다 값지다. 익명화해서 쌓고 주기적으로
패턴을 본다. **쌓기 전에 정할 것**: 무엇을 저장할지(원문? 추출 결과만?), 보관 기간,
사용자 고지. 원문은 개인정보가 섞이므로 기본은 저장하지 않는 쪽이 안전하다.

## 반드시 지킬 것

이 규칙들은 `AGENTS.md`에도 들어 있다.

**LLM은 '무엇을'만 뽑는다.** 소요시간·거리·도착 가능 여부를 만들게 하면 안 된다.
`10분 안에 마트 들렀다 회사`도 거절하지 않고 그대로 넘긴다 — 가능한지는 라우팅
결과로 코드가 판정하고, 이미 그 화면(`지금 출발해도 늦어요`)이 있다.

**기대값은 "제품이 어떻게 동작해야 하나"로 쓴다.** 2026-09-10에 이 실수를 했다.
`올리브용`의 기대값을 "못 잡으면 되묻기"로 적어놨는데, 그건 목의 한계를 제품
사양으로 굳힌 것이었다. Codex는 올리브영으로 교정한다. 13건을 상향하니 목 기준
실패가 6→17로 늘었고, 그게 격차를 정직하게 드러낸 것이다.

**러너의 '미검증'을 통과로 세지 말 것.** 처음 117/122로 보였던 게 실제로는
검증 105 중 실패 6이었다.

**인젝션 방어선은 프롬프트가 아니라 `server/src/schema.ts`다.**

**키를 서버로 옮겨도 문이 열려 있으면 의미가 없다.** 앱 토큰과 rate limit이 함께 가야 한다.

## LLM 실측에서 드러난 것

**`endpoints`를 4건 전부 놓쳤다.** 스키마엔 있는데 프롬프트가 시키지 못했다.
`회사 말고 집으로 가자`가 `dest=null`로 나왔다. 프롬프트에 예시 3개를 박아 넣었고,
**재실행으로 확인해야 한다** (`node server/run-llm.mjs`).

**비결정성이 실측됐다.** `구시까지 도착`이 36건 테스트에선 09:00, 147건에선 null.
같은 입력에 다른 답이다. `temperature=0`으로 낮췄지만 근본 해결은 아니다.
**실질 방어는 칩 UI** — 사용자가 뭘 알아들었는지 보고 고칠 수 있으면 비결정성이
치명상이 되지 않는다.
