# near 축 — 경유지를 경로의 어느 쪽 끝에 붙일지 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 경유지가 경로의 **어느 쪽 끝**에 붙어야 하는지를 표현하는 `near` 축을 추가한다 — "회사 근처 카페"가 집 앞 카페로 잡히지 않게.

**Architecture:** 새 순수 모듈 `src/lib/nearSide.ts` 가 규칙 전부를 갖는다(진행률 판정 + 물성 표). 추출 경계(`schema.ts`·프롬프트·목)가 `near` 를 실어 보내고, `runPlan` 이 **검색 뒤 후보를 거를 때** 한 번 적용한다. 채점(`score.ts`)은 건드리지 않는다 — `totalMin` 은 화면에 그대로 뜨는 값이라 페널티를 섞으면 거짓 시간이 된다.

**Tech Stack:** TypeScript · Expo SDK 57 / React Native · node:test (`tsx --test`) · Cloudflare Workers(server)

**Spec:** 별도 스펙 파일 없음. 설계는 2026-09-17 대화에서 확정했고 아래 "설계 근거" 절이 그 사본이다.

## 설계 근거 (스펙 대용)

### 왜 필요한가

지금 `scorePlan`(`src/lib/routePlan/score.ts:39`)이 보는 건 `totalMin` / `distanceKm` / 영업시간뿐이다. `ScoreContext` 에 위치 개념이 없다. 앵커 검색(`searchAtAnchors`)도 출발지·승차역·환승역·하차역·목적지를 **전부 같은 무게로** 훑는다. 그래서 "회사 근처 카페에서 커피 사서 갈게" 라고 해도 집 앞 카페가 우회 1분 더 짧으면 그쪽이 이긴다.

여행 단위 `order: 'auto' | 'locked'` 는 **순서**만 고정한다. 순서가 마지막이어도 **장소**는 출발지 옆일 수 있다. 그 구멍을 메우는 축이 `near` 다.

### near 를 누가 채우나 — 이번 단계는 ①+② 만

| 신호 | 예 | 판단 주체 | 이번 단계 |
|---|---|---|---|
| ① 사용자가 위치를 말함 | "회사 근처 카페", "집 앞에서", "내려서" | LLM (`near` 추출) | **포함** |
| ② 물건의 성질 | "커피 사서" → 들고 대중교통을 못 탄다 | 코드 표 (`nearSide.ts`) | **포함** |
| ③ `arriveBy` + 머무는 업종 | 결혼식 전 카페 | 코드 (dwell 필요) | **제외** |

②를 LLM 에 맡기지 않는 이유: "테이크아웃 커피는 대중교통에 못 들고 탄다"는 도메인 규칙이고, LLM 에 맡기면 케이스마다 흔들린다. AGENTS.md 의 "LLM은 '무엇을'만 뽑는다" 선이 그대로 적용된다 — 사용자가 **말한** 위치는 '무엇을'이지만, 물성 추론은 코드가 가진 표여야 재현된다.

③을 뺀 이유: 결혼식 케이스를 잡으려면 "머무는 경유지"를 알아야 하는데 그게 곧 체류시간이다. 지금 `dwellFor`(`src/state/runPlan.ts:65`)는 **검색어**만 보고 `why` 를 안 봐서 "커피 사기"와 "결혼식 전에 기다리기"가 똑같이 5분이다. dwell 을 고치는 건 `ScoreContext` 에 `arriveBy` 를 넣는 일이라 별도 단계다. ③ 없이 `arriveBy` 만으로 마지막 경유지를 뒤로 밀면 "9시까지 회사 가야 하는데 편의점 들러서"의 편의점까지 밀린다 — 오판이 이득보다 크다.

**이 단계가 잡는 것:** "회사 근처 카페에서 커피 사서 갈게"(①), "지하철 타고 가는데 커피 사서 갈게"(②).
**이 단계가 못 잡는 것:** "결혼식 가는데 근처 카페 들렀다 갈게" — 위치는 `근처`가 모호해 ①로 안 잡히고, 카페는 ②의 품목이 아니다. `docs/NEXT.md` 에 남긴다.

### 왜 채점이 아니라 후보 필터인가

세 자리를 검토했다.

1. `scorePlan` 에 페널티 → **기각.** `Scored.totalMin` 은 화면의 "◯◯시 도착"이 되는 값이다. 페널티를 섞으면 시간이 거짓이 된다.
2. `Scored` 에 별도 벌점 필드 → **기각.** 비교가 일어나는 자리가 넷(`partial` 빔 · `ranked.estC` 시드 · `select.ts` 최종 · `round2Plan`)이라 한 곳만 빠뜨려도 조용히 안 듣는다.
3. **검색 뒤 후보 필터 → 채택.** 한 자리에서 끝나고, `flexible: false`(= `candidates[0]` 고정)와 빔 열거 양쪽에 자동으로 듣는다.

### 하드 필터 금지 — 이게 이 계획의 제1 제약

`near` 로 걸렀더니 후보가 0개가 되면 **제약을 풀고 전부 되돌린다.** 2026-09-16 에 고친 버그(`샌드위치 파는 카페` 0건 → 경유지가 계획에서 통째로 증발)와 정확히 같은 모양이라, 같은 실수를 새 축으로 다시 들여오면 안 된다. 제약을 푼 사실은 `Slot.nearRelaxed` 로 남기고 화면이 한 줄로 말한다.

### 비목표

- 방문 **순서**는 건드리지 않는다. `near` 는 후보를 고르는 축이고, 순서는 계속 최적화가 정한다.
- 체류시간(`dwellMin`)은 건드리지 않는다.
- 하차 앵커(`AnchorKind`)로 정밀하게 자르지 않는다. 진행률 `s` 하나로 판정한다 — 모드에 무관하고, 틀려도 폴백이 받아 준다.

## Global Constraints

모든 태스크의 요구사항에 아래가 암묵적으로 포함된다.

- **기대값은 제품 사양으로 쓴다**(AGENTS.md). 목이 못 하는 걸 기대값에서 빼지 않는다.

- **node 테스트는 react-native 를 물 수 없다.** 순수 로직은 `src/lib/` 또는 `src/state/` 의 `.ts`(비-`.tsx`) 파일에 둔다. `src/state/plan.tsx` 는 테스트가 읽지 못한다.
- **`git add` 는 이 태스크가 건드린 파일만.** `git add -A` · `git add .` 금지. `node_modules` 는 어떤 경우에도 스테이징하지 않는다(과거에 워크트리 심링크가 커밋돼 메인 `node_modules` 가 지워진 사고가 있었다).
- 테스트 명령은 `npm test`. 파일 하나만 돌리려면 `npx tsx --test src/lib/nearSide.test.ts`.
- 주석·테스트 이름·커밋 메시지는 한국어. 기존 파일의 밀도와 어투를 따른다.

`src/lib/nearSide.test.ts` 를 통째로 만든다.

```typescript
import { test } from 'node:test';
import assert from 'node:assert/strict';
import { applyNear, matchesNear, nearFromCarry, resolveNear } from './nearSide.ts';
import type { LatLng } from './routePlan/types.ts';

/** 위도 37.5 위의 동서 직선. 127.0 이 출발지, 127.1 이 목적지 — 경도가 곧 진행률이다 */
const at = (lng: number): LatLng => ({ latitude: 37.5, longitude: lng });
const poly: LatLng[] = [at(127.0), at(127.1)];
const c = (id: string, lng: number) => ({ id, coord: at(lng) });
const startSide = c('s1', 127.01); // s ≈ 0.1
const middle = c('m1', 127.05);    // s ≈ 0.5
const endSide = c('e1', 127.09);   // s ≈ 0.9

test("matchesNear — 'any' 는 어디든 통과한다", () => {
  assert.equal(matchesNear('any', 0), true);
  assert.equal(matchesNear('any', 0.5), true);
  assert.equal(matchesNear('any', 1), true);
});

test("matchesNear — end 는 0.6 부터, start 는 0.4 까지. 가운데는 어느 쪽도 아니다", () => {
  assert.equal(matchesNear('end', 0.6), true);
  assert.equal(matchesNear('end', 0.59), false);
  assert.equal(matchesNear('start', 0.4), true);
  assert.equal(matchesNear('start', 0.41), false);
  // 0.5 는 양쪽 다 거절한다 — 애매한 자리를 양쪽에 다 넣으면 제약이 아니게 된다
  assert.equal(matchesNear('end', 0.5), false);
  assert.equal(matchesNear('start', 0.5), false);
});

test("applyNear('end') — 목적지 쪽 후보만 남는다", () => {
  const r = applyNear([startSide, middle, endSide], 'end', poly);
  assert.deepEqual(r.candidates.map(x => x.id), ['e1']);
  assert.equal(r.relaxed, false);
});

test("applyNear('start') — 출발지 쪽 후보만 남는다", () => {
  const r = applyNear([startSide, middle, endSide], 'start', poly);
  assert.deepEqual(r.candidates.map(x => x.id), ['s1']);
  assert.equal(r.relaxed, false);
});

test("applyNear('any') — 손대지 않는다", () => {
  const r = applyNear([startSide, middle, endSide], 'any', poly);
  assert.deepEqual(r.candidates.map(x => x.id), ['s1', 'm1', 'e1']);
  assert.equal(r.relaxed, false);
});

test('그쪽에 한 곳도 없으면 전부 남기고 relaxed — 경유지가 증발하면 안 된다', () => {
  const r = applyNear([startSide, middle], 'end', poly);
  assert.deepEqual(r.candidates.map(x => x.id), ['s1', 'm1'], '제약을 풀고 되돌린다');
  assert.equal(r.relaxed, true);
});

test('순서를 보존한다 — 앞 단계(주차 정책)가 매긴 우선순위를 뒤집지 않는다', () => {
  const e2 = c('e2', 127.08);
  const r = applyNear([e2, endSide], 'end', poly);
  assert.deepEqual(r.candidates.map(x => x.id), ['e2', 'e1']);
});

test('후보가 아예 없으면 relaxed 는 false — 못 찾은 것과 밀려난 것은 다른 사건이다', () => {
  const r = applyNear([], 'end', poly);
  assert.deepEqual(r.candidates, []);
  assert.equal(r.relaxed, false);
});

test('폴리라인이 2점 미만이면 진행률을 못 잰다 — 조용히 통과시킨다', () => {
  const r = applyNear([startSide, endSide], 'end', [at(127.0)]);
  assert.deepEqual(r.candidates.map(x => x.id), ['s1', 'e1']);
  assert.equal(r.relaxed, false, '못 잰 걸 "못 찾았다"고 말하면 거짓말이 된다');
});

test('nearFromCarry — 대중교통에서 커피는 end. 들고 탈 수 없다', () => {
  assert.equal(nearFromCarry('transit', ['카페'], '커피 사기'), 'end');
  assert.equal(nearFromCarry('transit', ['꽃집'], ''), 'end');
});

test('nearFromCarry — 차·도보는 표를 읽지 않는다. 들고 갈 수 있다', () => {
  assert.equal(nearFromCarry('car', ['카페'], '커피 사기'), 'any');
  assert.equal(nearFromCarry('walk', ['카페'], '커피 사기'), 'any');
});

test('nearFromCarry — 들고 타기 어려운 품목이 없으면 any', () => {
  assert.equal(nearFromCarry('transit', ['약국'], '약 사기'), 'any');
  assert.equal(nearFromCarry('transit', ['카페'], '결혼식 전에 기다리기'), 'any',
    '앉는 카페는 물성 신호가 아니다 — 그건 체류시간 축(다음 단계)이 볼 일이다');
});

test('resolveNear — 사용자가 말한 위치가 물성 표를 이긴다', () => {
  assert.equal(resolveNear('start', 'transit', ['카페'], '커피 사기'), 'start');
  assert.equal(resolveNear('end', 'car', ['약국'], '약 사기'), 'end');
});

test('resolveNear — 말하지 않았으면 물성 표로 떨어진다', () => {
  assert.equal(resolveNear('any', 'transit', ['카페'], '커피 사기'), 'end');
  assert.equal(resolveNear(undefined, 'transit', ['카페'], '커피 사기'), 'end');
  assert.equal(resolveNear(undefined, 'transit', ['약국'], '약 사기'), 'any');
});

 * near 축 — 이 경유지가 경로의 **어느 쪽 끝**에 붙어야 하는가.
 *
 * 왜 필요한가: 채점(`routePlan/score.ts`)은 총 소요시간만 본다. 그래서 "회사 근처
 * 카페"라고 말해도 집 앞 카페가 우회 1분 더 짧으면 그쪽이 이긴다. 여행 단위 `order`
 * 로도 표현되지 않는다 — 순서가 마지막이어도 장소는 출발지 옆일 수 있다.
 *
 * **하드 필터가 아니다.** 그쪽에 한 곳도 없으면 제약을 풀고 전부 되돌린다.
 * 0건이 곧 경유지 증발이라는 걸 2026-09-16 에 이미 한 번 겪었다
 * (`샌드위치 파는 카페` → 0건 → 계획에서 통째로 사라짐).
 */
import { projectOnCorridor } from './routePlan/corridor';
import type { LatLng, Mode, NearSide } from './routePlan/types';

/**
 * 진행률 경계. end 는 s ≥ 0.6, start 는 s ≤ 0.4 다.
 * 가운데 0.4~0.6 은 어느 쪽도 아니다 — 애매한 자리를 양쪽에 다 넣으면 제약이 아니게 된다.
 */
export const NEAR_SPLIT_S = 0.6;

/** s = 직행 폴리라인 위 진행 비율(0=출발지, 1=목적지). `routePlan/corridor.ts` 가 계산한다 */
export function matchesNear(near: NearSide, s: number): boolean {
  if (near === 'any') return true;
  return near === 'end' ? s >= NEAR_SPLIT_S : s <= 1 - NEAR_SPLIT_S;
}

/**
 * 들고 대중교통을 타기 어려운 것. 사면 곧 목적지여야 한다.
 *
 * `꽃`이 `꽃집`에도 걸리는 건 의도한 것이다 — 꽃을 사서 가는 길은 거의 항상 목적지 쪽이다.
 * 표를 늘리기 전에 오판 쪽을 먼저 보라: 틀리면 사용자가 말하지도 않은 제약이 붙는다.
 * 앉아서 머무는 업종(결혼식 전 카페)은 여기 신호가 아니다 — 그건 체류시간 축의 몫이다.
 */
const CARRY = /커피|음료|주스|스무디|아이스크림|빙수|케이크|꽃/;

/**
 * 물성 신호 — 사용자가 위치를 말하지 않았을 때의 기본값.
 *
 * `mode === 'transit'` 에서만 산다. 차·도보는 들고 갈 수 있으니 제약이 아니다.
 */
export function nearFromCarry(mode: Mode, queries: readonly string[], why?: string): NearSide {
  if (mode !== 'transit') return 'any';
  return CARRY.test([why ?? '', ...queries].join(' ')) ? 'end' : 'any';
}

/** 사용자가 말한 위치가 언제나 이긴다. 물성 표는 말하지 않았을 때만 읽는다 */
export function resolveNear(
  stated: NearSide | undefined,
  mode: Mode,
  queries: readonly string[],
  why?: string,
): NearSide {
  if (stated === 'start' || stated === 'end') return stated;
  return nearFromCarry(mode, queries, why);
}

/**
 * 후보를 그쪽 끝으로 좁힌다. **한 곳도 안 남으면 전부 되돌리고 `relaxed` 를 세운다.**
 * 입력 순서를 보존한다 — 앞 단계(주차 정책)가 매긴 우선순위를 뒤집으면 안 된다.
 */
export function applyNear<T extends { coord: LatLng }>(
  candidates: readonly T[],
  near: NearSide,
  poly: LatLng[],
): { candidates: T[]; relaxed: boolean } {
  // poly 가 2점 미만이면 진행률을 못 잰다. runPlan 은 항상 2점 이상을 주지만,
  // 못 잰 것을 '그쪽에 없다'로 말하면 거짓말이 된다 — 조용히 제약 없이 통과시킨다
  if (near === 'any' || candidates.length === 0 || poly.length < 2) {
    return { candidates: [...candidates], relaxed: false };
  }
  const kept = candidates.filter(c => matchesNear(near, projectOnCorridor(poly, c.coord).s));
  return kept.length > 0
    ? { candidates: kept, relaxed: false }
    : { candidates: [...candidates], relaxed: true };
}
```
