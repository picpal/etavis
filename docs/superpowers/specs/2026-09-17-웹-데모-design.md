# 웹 데모 — 해커톤 제출용 공개 링크

작성 2026-09-17. `docs/앱스토어-심사-검토.md`가 "웹 데모를 주 제출물로 확정"한 판단을 실제 배포까지 밀어낸다. codex 리뷰(2026-09-17)에서 나온 P1 6건·P2 4건을 반영한 2차 설계다.

## 왜

주최측 공지가 세 줄로 요약된다.

1. 설치 파일(APK·exe) 직접 배포 금지. **정식 스토어 링크** 또는 **핵심 기능을 바로 체험할 수 있는 웹 데모 링크**만 받는다.
2. 마감 **9/20 23:59:59**.
3. 심사 기간(~10/17) 내내 **로그인 없이** 접속 가능해야 한다. 링크가 죽으면 심사 대상에서 제외된다.

TestFlight 루트는 닫혀 있다. 현재 서명 팀 `6626BYCJG4`가 무료 Personal Team이라 제출 자체가 안 되고, 유료 계정 승인 1~2일 + 심사 왕복이 3일 안에 들어가지 않는다 (`memory/etavia-ios-build.md`).

그래서 웹 데모가 주 제출물이다. 이 문서는 "웹에서도 뜨게 한다"가 아니라 **"4주 동안 안 죽는 공개 링크를 만든다"**를 목표로 쓴다. 죽으면 0점이기 때문에, 이 문서에서 가장 많은 분량은 화면이 아니라 **폴백과 과금 방어**에 간다.

## 실측으로 이미 확인한 것 (2026-09-17)

- `npx expo export --platform web` → exit 0, 웹 번들 2.4MB, 자산 15개
- `localhost:8080`에 서빙 → **A1 홈이 그대로 렌더된다.** 콘솔 치명 오류 0
- 경고 3개뿐: `expo-file-system is not supported on web` ×2, `[expo-notifications] Listening to push token changes is not yet fully supported on web`

즉 "웹에서 뜨는가"는 답이 났다. 남은 건 흐름 완주와 가용성이다.

## 범위

**살리는 화면**: A1 홈 → A2 채팅 → A3 계산중 → A5 3안 비교 → A6 타임라인. 이 한 줄기가 제품의 주장 전체다 — 한 문장을 넣으면 경유지가 뽑히고 도착 시각이 나온다.

**건드리지 않는 것**: 네이티브 앱 동작, `src/lib/intent.ts` 목 규칙, 프롬프트(`server/prompts/extract-intent.md`), 채점기(`server/case-score.mjs`), A5·A6의 시각 불일치(`docs/NEXT.md` 최상단 항목 — 데모 체험을 막지 않는다).

**웹에서 빼는 것**: 진행중·주변·기록·설정 탭, 알림, 백그라운드 위치, 이동 기록 내보내기.

## 1. 장애 폴백 — 가장 먼저 한다

codex 리뷰의 핵심 지적이자 **1차 설계가 틀렸던 지점**이다. "상한을 치면 목으로 폴백된다"고 가정했지만, 그 폴백은 `/extract`에만 있다.

### 지금 코드가 하는 일 (검증 완료)

| 경로 | 실패 시 | 근거 |
|---|---|---|
| `/extract` | 로컬 목(`src/lib/intent.ts`)으로 강등, `source: 'local'` | `intentClient.ts:67` |
| `/route` | **throw → 계획 전체 `FAIL(direct)`** | `serverProvider.ts:67` → `runPlan.ts:89-93` |
| 장소 검색 | **throw → `FAIL(search)`** | `places.ts:159` |

`guard.ts`의 일일 상한은 피해를 묶는 장치가 아니라 **가용성 차단 스위치**다. 상한에 닿는 순간 A3에서 계획이 죽고, 심사자는 오류 화면을 본다.

### 고칠 것

**1-1. `serverProvider`에 목 강등을 붙인다.**

`serverProvider.ts`가 throw하는 자리에서 목 라우팅 공급자로 내려간다. 화면은 이미 `source`만 보므로(`A5` 판정 카드가 "서버 없이 추정한 값이에요"를 이미 표시한다) UI 변경이 필요 없다.

```
route() 실패 (네트워크·!res.ok·bad shape·timeout)
  → mockRouteProvider.route(...)  // haversine 추정
  → source: 'mock'
```

강등 조건은 **모든 실패**다. 429만 잡으면 안 된다 — 502·타임아웃·DNS 실패가 4주 동안 더 자주 온다.

**1-2. 장소 검색에 목 카탈로그 강등을 붙인다.**

`places.ts`에는 이미 `mockProvider`(`:107`)와 `CATALOG`(`:60`)가 있다. `getProvider()`는 **키가 없을 때만** 목으로 간다(`:287-294`). 런타임 fetch 실패에도 같은 길로 가야 한다.

`kakaoProvider`·`googleProvider`의 `search()`를 감싸는 얇은 래퍼를 둔다:

```
searchWithFallback(provider, ...args)
  try  → provider.search(...)
  catch → mockProvider.search(...)   // 빈 배열이 아니라 목 결과
```

**빈 배열로 떨어뜨리면 안 된다.** `runPlan`이 후보 0개를 "검색 실패"로 보고 슬롯을 버린다. 목 카탈로그가 답을 줘야 흐름이 산다.

**1-3. 강등을 화면에 말한다.**

목으로 내려갔으면 A5 판정 카드가 이미 그렇게 말한다. 장소 검색이 목으로 내려간 경우도 같은 문구 계열로 표시한다 — 심사자가 "이 앱이 거짓말한다"고 읽으면 안 된다. 제품 원칙(`AGENTS.md`: LLM이 소요시간을 지어내면 앱의 존재 이유가 무너진다)이 여기에도 적용된다.

### 테스트

`src/lib/routePlan/serverProvider.test.ts`, `src/lib/places.test.ts`에 fetch를 주입해 429·500·타임아웃·잘못된 JSON 각각에서 목으로 내려가는지 확인한다. 순수 함수 경계라 `npm test`로 돈다.

## 2. Workers `/places` 프록시

### 왜 필요한가

`src/lib/places.ts:156`이 `dapi.kakao.com`을 **클라이언트에서 직접** 부른다. `guard.ts`를 안 거치고, Kakao REST 키는 도메인 제한이 안 걸리는 종류다. 공개 번들에 박히면 누구나 무제한으로 쓴다. 키 회전은 해결책이 아니다 — 새 키도 똑같이 번들에 박힌다.

### 지금 서버에 없는 것

`server/src/kakao.ts:14`는 **Kakao Mobility 자동차 길찾기** URL 조립·정규화만 한다. Local 장소 검색은 없고, 키도 `KAKAO_MOBILITY_KEY`와 **별개**다(`server/src/index.ts:26`).

### 구현 목록

| 항목 | 내용 |
|---|---|
| secret | `npx wrangler secret put KAKAO_LOCAL_KEY` — 모빌리티 키와 별개 |
| 라우트 등록 | `server/src/index.ts:126`의 `known` 배열에 `/places` 추가 |
| 입력 검증 | query 길이(≤40), 좌표 한국 bbox(`isInKorea`와 같은 범위), radius 상한, size 상한. 스키마는 `server/src/schema.ts` 옆에 `placesSchema.ts`로 |
| 응답 정규화 | keyword·address 두 종류를 `Place` 형태로. 클라이언트 `kakaoProvider`의 매핑 로직을 서버로 옮긴다 |
| 캐시 | `CACHE` KV에 (query, 좌표 격자, radius) 키로. 같은 검색어가 라운드마다 반복되므로 효과가 크다 |
| 상한 | 아래 표 |
| 클라이언트 | `placesProvider`를 `/places` 호출로 교체. `planSearchFn()`(`:298`)과 **`DestinationSheet.tsx:86`의 직접 `getProvider()` 둘 다** |

### 상한값 — 기본값을 쓰면 정상 사용자가 429를 맞는다

`runPlan.ts:159` 주석이 명시한다: **후보 하나당 최대 25콜**(반지름 4라운드 + far 1라운드, 라운드마다 최대 5점 동시), 후보는 최대 3개. 즉 **슬롯 하나가 최악 75콜**이고, 경유지 2개면 150콜이 계획 한 건에서 나간다.

`PER_MIN`의 다른 값(`/extract` 10, `/route` 40)을 그대로 쓰면 계획 **한 건도** 못 끝낸다.

| 버킷 | 값 | 근거 |
|---|---|---|
| `PER_MIN['/places']` | 300 | 계획 1건 최악 150콜 × 여유 2배 |
| `PER_MIN_IP['/places']` | 900 | 다른 경로와 같은 3배 비율 |
| `PER_DAY['/places']` | 미정 | **카카오 개발자 콘솔에서 실제 무료 쿼터를 확인한 뒤 그 30% 선으로 정한다.** 다른 `PER_DAY` 값들처럼 근거를 주석에 적는다 (`guard.ts:38-50` 형식) |

**캐시 hit도 상한을 소모한다**(codex 지적). `/places`는 캐시 hit를 일일 카운터에서 빼는 쪽으로 간다 — 바깥 API를 안 불렀으면 돈이 안 나갔다.

### 타임아웃

클라이언트에 5초 타임아웃을 건다. `runPlan`의 `DEFAULT_TIMEOUT_MS`가 12초라, 프록시가 느려지면 계획 전체가 타임아웃으로 죽는다. 5초에 끊고 §1-2의 목 폴백으로 내려간다.

### 이걸 3일 안에 못 하면

대안은 **키 회전이 아니라 키 제거**다. 웹 번들에서 Kakao·Google 클라이언트 키를 완전히 빼고 목 카탈로그(`CATALOG`)로만 돈다. 심사자에게는 지원 문장 예시를 화면에 명시한다. 프록시 구현과 이 대안 사이의 판단은 9/18 오전에 한다.

## 3. 플랫폼 shim

Metro가 웹에서 `.web.ts`를 일반 `.ts`보다 먼저 고른다. 기존 파일은 손대지 않는다.

| 파일 | 웹 구현 |
|---|---|
| `src/lib/prefs.web.ts` | `localStorage`. **읽기·쓰기·JSON 파싱 전부 try/catch** — 시크릿 모드·차단 설정에서 throw한다 |
| `src/lib/trackLog.web.ts` | no-op. 내보내기 UI는 웹에서 안 보인다 |
| `src/lib/currentPlace.web.ts` | §4 |

### 통째로 no-op 하면 안 되는 두 곳

**`backgroundLocation`** — `toFix()`가 여기서 export되는데(`backgroundLocation.ts:83`) `tracker.tsx:455,466`이 **전경** GPS 변환에 쓴다. 배경 추적만 끄고 `toFix`는 공통 구현으로 남긴다.

```
backgroundLocation.web.ts
  startBackgroundLocation / stopBackgroundLocation / subscribeBackgroundLocation → no-op
  toFix → 네이티브와 같은 순수 변환 (재사용 또는 동일 구현)
```

**`notifications`** — `notifications.web.ts`를 만들어도 `App.tsx:8`이 `expo-notifications`를 **직접** import한다. `NotificationBridge`(`App.tsx:71`)도 웹에서 inert 리스너를 등록한다. Bridge를 `src/NotificationBridge.tsx` / `.web.tsx`로 분리해 웹에서는 `null`을 반환하게 한다.

### 추적 자체를 꺼야 한다

A6 진입이 즉시 `confirmPlan()`을 부르고(`TimelineScreen.tsx:101`), Tracker가 `live` 모드로 `expo-location`을 시작한다(`tracker.tsx:390`). 배경 shim만으로는 **웹에서 위치 추적이 안 꺼진다** — 심사자가 A6에 들어가는 순간 위치 권한 팝업이 또 뜬다.

`tracker.tsx`에 `Platform.OS === 'web'`이면 `live` 모드 진입을 막는 가드를 둔다. 데모에 지오펜스는 필요 없다.

### 타입 주의

TypeScript는 확장자 없는 import를 검사할 때 일반 `.ts` 계약을 본다. 웹 shim에서 export를 빠뜨려도 `tsc --noEmit`이 못 잡는다. **최종 검사는 실제 웹 export + 브라우저 완주**다.

## 4. 출발지

GPS를 시도하고, 실패·거부·타임아웃이면 고정 데모 출발지로 간다.

- 고정 지점: **여의나루역** `{ latitude: 37.5271, longitude: 126.9327 }` (`mockData.ts:225`의 `HOME`). 목 데이터셋이 여의도↔목동 축으로 짜여 있고 주변에 올리브영·파리바게뜨가 실재한다
- `expo-location`의 `reverseGeocodeAsync`는 **웹에서 지원되지 않는다**. 역지오코딩을 건너뛴다
- `navigator.geolocation.getCurrentPosition`에 **`timeout: 5000`을 명시한다.** 없으면 콜백이 영영 안 와서 출발 좌표가 null로 남는다
- 폴백으로 갔으면 출발지 행에 **`데모 출발지 · 여의나루역`**이라고 쓴다. 실제 위치처럼 보이면 심사자가 오작동으로 읽는다

## 5. 웹 전용 UI

**탭바는 웹에서 숨긴다.** 1차 설계에서는 "구조를 보여주려 남긴다"고 했는데 뒤집는다. `TabBar.tsx:80`이 지금 Today·Nearby·History·Settings로 **실제 이동**한다. 3일 안에 네 화면을 `준비 중`으로 바꾸는 것보다 숨기는 쪽이 짧고 안전하다. 미완성 화면으로 보내는 게 더 나쁘다.

## 6. 배포 배선

`app.config.js:11`이 빌드 타임에 값을 주입한다. **Pages 환경변수가 없으면 앱이 조용히 목으로 돈다** — 오류 없이 품질만 떨어져서 알아채기 어렵다.

| 항목 | 값 |
|---|---|
| 빌드 | `npx expo export --platform web` |
| 출력 | `dist/` |
| Node | 24 (`.github/workflows/testflight.yml`과 같은 버전) |
| 주입할 env | `SERVER_URL`, `APP_TOKEN` |
| **주입하지 않을 env** | `KAKAO_REST_KEY`, `GOOGLE_PLACES_KEY` — §2 프록시 이후 클라이언트에 불필요 |
| 호스팅 | Cloudflare Pages (Workers와 같은 계정) |
| CORS | 확정된 production origin을 `server/wrangler.toml:8`의 `ALLOWED_ORIGINS`에 추가 |

### 순서

1. Workers 먼저 배포(`/places` + `ALLOWED_ORIGINS`)
2. Pages 배포
3. 시크릿 모드로 접속 검증
4. 롤백은 역순

### 제출 후

production 브랜치 자동 배포를 **동결한다.** 9/21~10/17 사이의 커밋이 심사 중인 링크를 바꾸면 안 된다.

### SPA 라우팅

Expo 57 웹 출력 기본값은 `single`(SPA)이고, Cloudflare Pages는 최상위 `404.html`이 없으면 미일치 경로를 `index.html`로 보낸다.

**실측(2026-09-17)**: export 산출물은 `index.html` · `favicon.ico` · `metadata.json` · `_expo/` · `assets/` 뿐이고 **`404.html`이 없다.** 전제가 성립한다.

그래도 배포 후 `/home`·`/plan`·`/timeline`을 주소창에 직접 입력하고 강력 새로고침해 확인한다 — Pages 설정이나 `app.json`의 `web.output`이 바뀌면 전제가 뒤집힌다.

## 7. 과금·남용 방어

`APP_TOKEN`은 번들에서 보인다. **CORS는 비용 공격을 막지 않는다** — 공격자는 브라우저가 아니라 curl로 `Origin` 없이 부르고, 서버는 Origin 없는 요청을 거부하지 않는다. KV 카운터도 비원자적이라 동시 요청에서 몇 건은 샌다.

그래서 방어선을 서버 코드가 아니라 **공급자 콘솔**에도 둔다.

| 항목 | 조치 |
|---|---|
| Google Cloud | 데모 전용 프로젝트 + Routes/Places에 **일일 하드 쿼터**. 결제 예산 알림 |
| Kakao | 개발자 콘솔 일일 쿼터를 `PER_DAY['/places']`보다 약간 위로 |
| OpenAI | 사용량 상한. `/extract` 1,200/일이 이미 걸려 있다 |
| 최종 방어 | §1 폴백 — 상한에 닿아도 목으로 내려가 **화면은 계속 돈다** |

마지막 줄이 핵심이다. 상한을 완벽히 막을 수는 없지만, 상한에 닿아도 데모가 안 죽게는 할 수 있다.

## 8. 검증

### 8-1. 제스처 — 실제로 눌러 봐야 안다

Reanimated 4.5.1·gesture-handler 2.32는 Expo 57의 공식 웹 지원 버전이고 `react-native-draggable-flatlist`에도 웹 측정 코드가 있다. 원칙상 silent no-op은 아니다.

문제는 **A6가 세 제스처를 중첩**한다는 것이다.

| 제스처 | 위치 |
|---|---|
| 세로 드래그 재정렬 | `TimelineScreen.tsx:291` |
| 카드 내부 가로 스와이프 삭제 | `TimelineScreen.tsx:131` |
| `Pressable.onLongPress`로 드래그 활성화 | `TimelineScreen.tsx:166` |

draggable-flatlist 4.0.3은 React 19 / RN 0.86 / Reanimated 4 조합을 명시적으로 보증하지 않는다. **Chrome 마우스와 모바일 터치 양쪽에서 실제로 재정렬하고 `onDragEnd`까지 확인하기 전에는 제출하지 않는다.**

**대체안(싸다)**: 웹에서만 카드에 위/아래 이동 버튼을 붙인다. 드래그와 Sheet 드래그 닫기는 핵심 기능이 아니다. Sheet는 스크림 탭 + 닫기 버튼만 살면 된다.

### 8-2. 완주 체크리스트

실제 배포 URL에서 돈다. localhost는 CORS 조건이 달라 증거가 못 된다.

- [ ] A1 → A2 → A3 → A5 → A6 완주
- [ ] GPS **허용** / **거부** 각각에서 완주
- [ ] `/route` 강제 실패(429/502) → 목 강등으로 계속 진행
- [ ] 장소 검색 강제 실패 → 목 카탈로그로 계속 진행
- [ ] `/extract` 실패 → 로컬 목 강등(`source: 'local'`)
- [ ] `/home`·`/plan`·`/timeline` 주소창 직접 입력 + 강력 새로고침
- [ ] A6 드래그 재정렬 — 마우스 / 터치
- [ ] Sheet 열기·닫기 — 스크림 탭 / 닫기 버튼 / 드래그
- [ ] 한글 IME 입력 (A2 채팅)
- [ ] **시크릿 모드** 접속 (공지 2-1 요구사항)
- [ ] 다른 네트워크(LTE) · 모바일 브라우저

### 8-3. 4주 모니터링

`/health` 핑으로는 부족하다. 그건 Worker가 살아 있다는 말이지 데모가 돈다는 말이 아니다. **A1 입력 → 결과까지 확인하는 외부 합성 모니터**를 걸고 실패 시 알림을 받는다.
