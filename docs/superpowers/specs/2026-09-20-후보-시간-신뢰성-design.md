# 후보 시간 신뢰성 — 교체 시트의 숫자를 같은 자로 잰다

작성 2026-09-20. 서교동 → 코엑스 대중교통, 이마트(무거움)·CU 두 곳. 계획은 `provider_legs`("구간마다 시간표 조회")로 직행 45분·들르기 +39분·도착 23:47 을 냈다. CU 교체 시트를 열자 **30곳 전부 "약 −32분 · 경로에서 0m · 추정"** 이었고 전부 홍대였다. 하나를 고르자 +39분이 +7분, 23:47 이 23:15 로 바뀌었는데 배너는 여전히 "구간마다 시간표 조회", '약'은 사라졌고, 버튼은 "23:15 도착 경로로 계속"이 됐다. 지어낸 32분이 실측인 척 확정 가능한 계획까지 흘러갔다.

이 문서는 설계다. 코드는 없다. `src/`·`server/`는 건드리지 않았다.

## 1. 근본 원인 — "자 섞기"

네 결함은 하나다. **등급이 다른 두 수를 산술로 섞고, 결과를 등급 없이 내보낸다.** 이름을 붙이면 **자 섞기(mixed-ruler arithmetic)** 다. D1 은 실측 합계에서 추정 합계를 뺐다 — 대중교통 실측 구간엔 접근·대기 8분씩이 들어 있고 추정(`km × ρ`, ρ = 45/13 ≈ 3.5분/km)엔 없으니, 홍대 안 300m 차이가 −32분으로 찍힌다. D2 는 **여행 전체** 차이를 **경유지 한 곳** 도착에 더했다 — 단위가 다른 두 수를 더한 것이라 출발(22:23)보다 이른 도착(21:58)이 나온다. D3 은 등급 표시가 **계획 단위**(`timingSource`)에만 있고 **변형 단위**(교체한 뒤의 `Rescored.estimated`)를 `provider_legs` 가지가 버린다 — 값은 추정으로 떨어졌는데 문구는 계획의 등급을 그대로 읽는다. D4 는 시간 축을 무시하고 후보를 잘라 **시간이 같은 30곳**을 **선택지 30개**로 늘어놓았고, 그 위에 D1 이 같은 −32 를 30번 찍었다. 각각을 따로 고치면 다음 화면에서 다시 난다. 깨진 건 불변식 하나다.

## 2. 지킬 불변식

> **사용자가 견주는 두 수는 같은 자로 잰 값이다. 화면에 나가는 모든 시간 값은 자기 등급을 들고 다니고, 등급을 문구로 바꾸는 곳은 `timingCopy` 하나다.**

검증 가능한 형태로 셋으로 쪼갠다.

1. **차이는 같은 자에서만 난다.** `Δ = a − b` 를 만들 때 a 와 b 는 같은 추정기로 만들었거나 둘 다 실측이다. 실측 − 추정은 존재하지 않는다.
2. **차이는 난 자리에만 붙는다.** 경유지 i 를 바꾸면 바뀌는 구간은 정확히 둘(`prev→i`, `i→next`)이다. i 의 도착엔 앞 구간 차이만, 총합엔 둘의 합이, 뒤 경유지 도착엔 둘의 합이 붙는다.
3. **등급은 값에 붙어 다닌다.** `Rescored`·`Alternative`·`Candidate` 가 `cls: 'measured' | 'estimated'` 를 들고, 화면은 그 값을 `timingCopy` 에 넘겨 '약'을 받는다. 문자열이나 계획 단위 등급으로 추측하지 않는다.

### 어디서 막나 — 재료를 없앤다

"조심하자"가 아니라 **뺄 재료를 손에 쥐어 주지 않는다.**

| 층 | 장치 | 효과 |
|---|---|---|
| 타입 | `src/lib/routePlan/types.ts` 에 `TimingClass = 'measured' \| 'estimated'`, `Timed = { min: number; cls: TimingClass }`. `Rescored` 에 `cls`·`legCls: TimingClass[]`·`delta?: { totalMin: Timed; arrivals: Timed[] }` 추가. `Alternative.addedMin`·`arriveMin` 은 `Timed`. `Candidate`(`mockData.ts`)에 `cls: TimingClass` | 등급 없는 시간 값이 화면 타입에 없다 |
| 관문 | `PlanResult.rescoreFrom(base: Visit[], visits: Visit[]): Rescored` 하나가 **기준 안 대비 변형의 시간과 차이**를 낸다(§3 D1). `rescore(visits)` 는 남되 `delta` 를 채우지 않는다 | 차이는 관문 안에서만 만들어지고, 관문은 같은 자를 쓴다 |
| 호출부 | `slotCandidates` 는 `timing.totalMin` 을 **받지 않는다**(시그니처에서 뺀다). `addedMin` 은 `rescoreFrom(...).delta` 에서만 온다. `runPlan.ts:443-450` 트렌드 스왑의 `addedMin` 도 같다 | 빼기를 쓸 수 있는 자리가 브리지에 없다 |

## 3. 결함별 설계

### D1 — 실측에서 추정을 뺀다 (`planFlowBridge.ts:177`)

**선택: 같은 자 차이(leg-differential).** WAPE 보정과 "숫자 안 보이기"는 버린다. 이유는 아래.

`rescoreFrom(base, visits)` 는 `scorePlan` 을 두 번 도는 게 아니라 **구간마다** 등급을 정한다. 기준 안 `base` 의 구간 k 와 변형 `visits` 의 구간 k 를 짝지어(`from>to` id 로 비교):

```
구간 k 가 두 안에서 같다        → 기준 값 그대로, 등급 그대로
구간 k 가 다르다:
  둘 다 lookup 적중            → M_new, cls measured, Δk = M_new − M_old
  아니면                        → E_new = km(new)×ρ, E_old = km(old)×ρ  (같은 추정기)
                                  값 = max(E_new, M_old + (E_new − E_old))   (M_old 없으면 E_new)
                                  cls estimated, Δk = E_new − E_old
```

`delta.totalMin = ΣΔk` (등급은 바뀐 구간들의 최저), `delta.arrivals[i]` 는 i 까지의 ΣΔk. 우회는 `detourM = |corridorOf(cand).y|` — 회랑 수직거리다. 기하값이라 등급이 없고, 추정 km 에서 실측 km 를 뺀 "0m" 이 사라진다.

**왜 같은 자인가.** `docs/transit-추정-오차.md` 가 답을 이미 적어 뒀다 — 구간 추정 오차는 bias −1.1분, MAE 5.1분이다. 한쪽으로 쏠린 게 아니라 흩어져 있어서 **상수를 어떻게 보정해도 RMSE 는 9% 준다.** 그러니 WAPE 로 추정을 끌어당겨도 화면 숫자는 그만큼밖에 안 좋아지고, 대신 "보정된 추정"이라는 등급 없는 숫자가 하나 더 생긴다. 반면 **같은 자로 잰 두 값의 차**는 계통 오차(접근·대기 8분 등)가 서로 지워진다. 홍대 안 300m 옆 후보의 Δ 는 `0.3km × 3.5 ≈ 1분` — "비슷해요"가 나온다. 정직하다. `M_old + (E_new − E_old)` 는 실측 기준 위에 그 차이를 얹은 것이라 절대 시각도 같은 논리로 선다. `E_new` 하한은 음수 방지용이지 보정이 아니다.

**왜 숫자를 아예 안 보이는 건 아닌가.** `provider_direct_only` 는 이미 '약'을 붙여 경유 추정치를 보여 주고 확정까지 허용한다. 그 목소리와 맞춘다. 다만 **묶음 안**(§4)에서는 숫자를 안 낸다 — 거기서 1분 차이는 추정기 잡음이라 숫자가 정보가 아니다.

**바꿀 파일**

- `src/lib/routePlan/plan.ts` — `rescoreFrom` 추가. `alternatives` 계산(`:196-213`)도 이걸로. `rescore` 의 `Rescored` 에 `cls`·`legCls` 채움.
- `src/lib/routePlan/score.ts` — `Scored` 에 `legCls` 추가(`hit` 이면 measured). `estimateLegKm` 은 그대로.
- `src/state/planFlowBridge.ts` — `slotCandidates(result, slots, visits, idx)` 로 시그니처 축소. `effectiveVisits` 는 `rescoreFrom(option.visits, visits)`. `alternativeToCandidate` 는 `Timed` 를 받고 `note` 에 ' · 추정' 을 붙이지 않는다(등급은 `cls` 가 든다).
- `src/state/runPlan.ts:443-472` — 트렌드 스왑의 `addedMin`·`arriveOk` 판정을 `rescoreFrom` 으로.
- `src/data/mockData.ts` — `Candidate.cls`.

**사용자가 보는 것**: 홍대 30곳이 "−32분" 대신 "비슷해요"(묶음이면 숫자 없음). 삼성역 CU 는 "약 +6분". 시드로 실측된 후보는 "+4분"(약 없음).

### D2 — 전체 차이를 한 지점에 더한다 (`planFlowBridge.ts:181` + F2 쌍둥이)

A5: `alternativeToCandidate(alt, query, alt.arriveMin, ...)` — `arriveMin = base.arrivals[idx] + delta.arrivals[idx]` 는 `rescoreFrom` 이 이미 냈다. 브리지는 더하지 않는다. 21:58 은 구조적으로 못 나온다(앞 구간 Δ 만 붙고, 그 Δ 는 `max(E_new, …)` 로 하한이 있다).

A6(확정 뒤, 3단계): `StopState.replaceDeltaMin` 을 `replaceDeltaInMin`·`replaceDeltaOutMin` 으로 나눈다. `computeChain` 은 들어오는 구간에 `In`, 나가는 구간(다음 스톱의 `legBetween(prev, …)` 또는 `dest`)에 `Out` 을 붙인다. `Candidate` 가 `addedMin` 외에 `arriveDeltaMin`(= 앞 구간 Δ)을 들고 나오면 `applyCandidate` 는 `In = arriveDeltaMin 차이`, `Out = addedMin 차이 − In` 으로 나눈다. `TimelineScreen.tsx:52` 는 후보의 `arriveAt` 을 그대로 쓴다 — 브리지가 낸 값이라 다시 더할 이유가 없다. `dataset.legs` 에 `cls` 를 실어 `toLegacyPlan` 이 `dataset.legEstimated` 를 세우고, `TimelineScreen.tsx:34`·`TabStubScreens.tsx:314`·`tracker.tsx:261,302` 가 세 번째 인자로 넘긴다 — 지금은 두 인자만 넘겨 확정 뒤 화면이 계획 등급만 읽는다.

### D3 — `provider_legs` 가 `legEstimated` 를 버린다 (`timingCopy.ts:38`)

`timingCopy` 를 (source, legEstimated) 표 하나로 다시 쓴다. `legEstimated` 가 참이면 **어느 source 든** '약'이 붙고 판정이 꺼진다. F5 의 `provider + true → showVerdict: true` 도 함께 뒤집는다 — 파일 머리말이 이미 그렇게 말하고 있고, `runPlan.ts:465-469` 가 같은 이유로 추정 위 스왑을 거부한다. 문구는 §6.

`deltaCopy(t: Timed): string` 을 같은 파일에 둔다. `CandidateSheet.addedLabel` 은 이걸 부른다. `signedMin` 의 '−' 처리는 그대로 옮긴다.

### D4 — 한 동네가 목록을 독점한다 (`corridorSearch.ts` `byCorridor` **와** `attach`)

**규칙: 진행률 버킷 라운드로빈.** 후보를 경로 위 위치로 묶고, 묶음마다 한 개씩 돌아가며 뽑아 `max` 에서 자른다.

- 버킷 키: 회랑 검색은 `floor(s × samples)` (s = `crossTrack(...).progressM / L`, 샘플 5 → 버킷 5). 앵커 검색은 `anchorId` (이미 가장 가까운 앵커로 붙여 놓는다).
- 버킷 안 순서: 지금 기준 그대로(회랑 수직거리 / `anchorWalkM`).
- 뽑기: 버킷을 진행 순으로 놓고 라운드로빈. 버킷이 비면 건너뛴다. `max` 에서 멈춘다.
- `side` 가 있으면 두 패스 — near 쪽 버킷들 먼저 라운드로빈, 그다음 반대쪽. `nearFirst` 의 "그쪽 먼저, 반대쪽 안 버림" 계약을 그대로 지킨다.
- 이름은 `spreadCut(list, bucketOf, rankOf, max, near?)`. `nearFirst` 자리를 대체하고 `byCorridor`·`attach` 둘 다 부른다. 회랑 컷과 앵커 컷이 같은 함수를 쓴다는 주석이 이미 있으니 거기 얹는다.
- 보장: 공급이 있는 버킷 B 개면 각 버킷은 최소 `⌊max / B⌋` 자리를 얻는다(5개면 6곳). 서교동·홍대입구가 30을 다 먹지 못한다.

**비용: `/places` 0회 추가.** 같은 검색 결과를 다르게 자를 뿐이다. 반지름 사다리의 `target` 판정(전체 8곳이면 멈춤)은 손대지 않는다 — 버킷별 목표로 바꾸면 회차마다 +5콜이고, 이 실행에서 삼성역 앵커는 첫 회차에 이미 후보를 줬다(밀린 것이지 없던 게 아니다). 필요해지면 그때 별도 단계.

**주의**: `runPlan.ts:275` 의 `sided.candidates.slice(0, MAX_CANDIDATES)` 가 한 번 더 자른다. `applyNear` 는 입력 순서를 보존하므로 `spreadCut` 의 라운드로빈 순서가 그대로 살아 통과한다. 뒤 단계 `enumerate` 는 `estC` 로 정렬하므로 순서에 안 민감하다.

## 4. 후보 묶기 — 같은 자리는 선택지 하나다

**정의**: 두 후보가 (같은 `anchorId` 이고) 서로 250m 안이면 한 묶음. `SAME_TIME_M = 250` 은 제품 문장이다 — **"250m 안은 같은 시간 선택지다."** 도보 3분이고, 구간 추정 MAE 5분·같은 OD 의 출발 시각 차이 20% 흔들림(`docs/transit-추정-오차.md`)보다 작다. 그 안의 시간 차이는 정보가 아니라 잡음이다. 묶기는 탐욕 — 후보를 Δ 오름차순으로 훑으며 기존 묶음 중심 250m 안이면 합치고 아니면 새 묶음.

**대표**: 묶음에 실측된 후보(두 구간 다 `measured`)가 있으면 그것. 없으면 `scoreTrend` 1위. 묶음의 시간은 대표의 시간이고 등급도 대표의 등급이다.

**시트가 말하는 것**:

- 묶음 머리: `같은 자리 4곳 · 시간 차이 없어요` — 대표의 추가시간·도착만 한 번 보인다.
- 묶음 안 순서: 시간이 아니다. `scoreTrend`(`signals.google` 평점·`signals.blog` 언급) → 영업(`closing_soon` 은 뒤로, `closed` 는 이미 `rankCandidates` 가 뺀다) → 이름. 이유 문구는 지금처럼 `reasons.join(' · ')`.
- 묶음 사이 순서: `추가시간` 탭은 대표 Δ, `추천` 탭은 대표 trend 점수.
- 묶음이 1곳이면 머리 없이 지금 카드 그대로.

**어디에**: `src/lib/routePlan/cluster.ts` 순수 함수 `clusterCandidates(cands, distanceM)`. 브리지의 `slotCandidates` 가 `Candidate` 에 `clusterId`·`clusterSize` 를 붙이고, `CandidateSheet` 가 그걸로 머리를 그린다. `rankCandidates` 는 묶음 단위로 정렬하도록 키를 대표에서 읽는다.

**실제로 재야 할 자리 수**: 30곳이 5 버킷에 퍼지면 묶음은 5~10개다. 시드가 이미 재 둔 것(V=1 은 8안, V=2 는 4안 안팎)이 묶음 몇 개를 공짜로 실측으로 만든다 — D4 로 후보가 퍼지면 `pickSeeds` 의 `estC` 상위가 서로 다른 묶음에 걸릴 확률도 오른다. 나머지 묶음은 **시트를 열 때 재지 않는다**(0회). 고를 때 그 하나만 잰다(6단계, 2회). 열 때마다 5~10 묶음 × 2구간 = 10~20회를 쓰는 안은 300/일 아래에서 성립하지 않는다.

**지시문에 대한 반론 하나**: "묶음 = 재야 할 위치 수"는 맞지만 그걸 **시트 열기 비용**으로 삼으면 안 된다. 사용자는 30곳 중 한 곳을 고르지 열 곳을 고르지 않는다. 재는 건 고른 것 하나면 된다.

## 6. 신뢰 표면 — 상태별로 사용자가 읽는 것

`timingCopy(source, mode, legEstimated)` 의 새 표. 기존 문구는 한 글자도 안 바꾸고 `legEstimated` 행만 는다.

| source | legEstimated | approx | banner | showVerdict |
|---|---|---|---|---|
| `provider` | false | `''` | `null` | true |
| `provider` | **true** | `'약 '` | `'바꾼 매장 구간은 추정이에요'` | **false** (F5 뒤집음) |
| `provider_legs` | false | `''` | `'구간마다 시간표 조회 · 체류 뒤 배차는 미반영'` | false |
| `provider_legs` | **true** | `'약 '` | `'구간마다 시간표 조회 · 바꾼 매장 구간은 추정'` | false |
| `provider_direct_only` | * | `'약 '` | 기존 | false |
| `estimate` / undefined | * | `'약 '` | 기존 | false |

6단계가 들어오면 `true` 행의 배너 뒤에 재는 동안 ` · 시간표 조회 중` 을 붙이고, 응답이 오면 `legEstimated` 가 거짓이 되어 위 행으로 올라간다. 6단계 전에는 "조회해요" 같은 약속을 문구에 넣지 않는다 — 없는 기능을 말하면 거짓말이다.

`deltaCopy(t: Timed)`:

| cls | 값 | 문구 |
|---|---|---|
| measured | +7 | `+7분` |
| measured | −3 | `−3분` |
| measured | 0 | `같아요` |
| estimated | \|Δ\| < 3 | `비슷해요` |
| estimated | +6 | `약 +6분` |

카드의 다른 칸: 도착은 `cls` 가 estimated 면 `약 23:15`, 아니면 `23:15`. note 는 `CU · 경로에서 120m` — ' · 추정' 접미를 뗀다(등급은 '약'이 말한다, 두 군데서 말하면 한쪽이 틀린다). 묶음 머리는 §4.

**상태 넷을 화면 하나로**(A5 헤드라인 · 배너 · 버튼):

| 상태 | 헤드라인 | 배너 | 버튼 |
|---|---|---|---|
| 전부 실측 | `23:47 도착` (+판정) | 없음 / 구간 배너 | `23:47 도착 경로로 계속` |
| 일부 추정 (바꾼 뒤) | `약 23:41 도착` | `구간마다 시간표 조회 · 바꾼 매장 구간은 추정` | `약 23:41 도착 경로로 계속` |
| 전부 추정 | `약 …` | 기존 모드별 배너 | `약 … 경로로 계속` |
| 모름 | 시간 칸 대신 `시간을 알 수 없어요` | `이 후보는 경로에 붙일 수 없어요` | 고르기 비활성 | 

"모름"은 `rescoreFrom` 이 후보를 회랑에 투영 못 할 때(직행 폴리라인이 2점 미만·ρ 가 추정 출처)만이다. 지금 코드로는 직행이 실패하면 계획 자체가 FAIL 이라 A5 까지 안 오므로, 이 행은 타입에 자리만 만들고(`cls` 에 `'unknown'` 을 넣지 않는다 — `Timed | null`) 화면은 null 이면 고르기를 막는다.

**바꾸면 dirty 로 만들고 다시 계산을 강제할까 — 아니다.** 근거 셋.

1. 다시 계산은 `/transit` 10 + `/places` 10~20 + 12초다. 그런데 **고른 후보를 재 준다는 보장이 없다** — 시드는 `estC` 로 뽑히고 사용자의 선택은 시드가 아닐 수 있다. 비싸면서 진실을 안 산다.
2. `provider_direct_only` 는 이미 '약'을 붙인 채 확정을 허용한다. 같은 목소리다. 다르게 하면 왜 어떤 '약'은 되고 어떤 '약'은 안 되는지 사용자가 설명받아야 한다.
3. 진짜로 원하는 건 "고른 것을 잰다"이고 그건 2회면 된다(6단계). 강제 재계산은 그 자리에 놓인 비싼 대체품이다.

그래서: 바꾸면 **'약' + 배너 + 판정 꺼짐**으로 확정을 허용하고, 6단계가 들어오면 고르는 순간 2회를 재서 '약'을 지운다. dirty 배너("조건이 바뀌었어요")는 지금처럼 `isStale`·경유지 빼기에만 쓴다.
