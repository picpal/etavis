## 차단 사유

### ① 리뷰어는 한국에 없다 — Guideline 2.1

Apple 심사는 미국·호주 등지에서 진행된다. 리뷰어 위치가 기준이 되는 순간 국내 전용 로직이 전부 실패로 보인다.

| 코드 | 내용 |
|---|---|
| `src/lib/routePlan/serverProvider.ts` | 라우팅이 카카오 모빌리티. 국내 전용 |
| `src/data/mockData.ts` | 목 좌표가 평창 · 신정동 |
| `src/state/tracker.tsx` | 경로에서 5km 이상 멀면 판정 중단 → 리뷰어는 항상 이탈 상태 |

**해법 — 목 데이터셋을 정식 진입점으로 승격한다.** 자산은 이미 있다.
개발 메뉴의 `이 데이터셋으로 진행중 시작`을 **"예시로 둘러보기"** 같은 정식 기능으로 올리면,
리뷰어가 위치와 무관하게 전체 흐름을 본다. ③도 같이 해결된다(개발 토글은 빼고 데모 진입점만 남김).

보조 수단:
- **데모 영상** — App Review Information → Notes에 비공개 URL. 국내 앱들이 통과하는 주력 수단
- **Review Notes** — "대한민국 전용 서비스, 국외 좌표에는 경로 데이터가 없음" + 재현 절차를 영문으로
- **배포 국가를 대한민국으로 한정** — 심사 면제는 아니지만 한국 전용의 정당성이 된다

2.1의 실제 발동 조건은 "해외에서 안 되는 것"이 아니라 **"열었더니 빈 화면·크래시·무반응"**이다.
우아하게 실패하면 넘어간다.

### ② OpenAI 키가 401이다 — 심사 무관, 데모의 핵심

~~저장소에 `.env`가 없어 100% 목 앱이 나온다~~ → **취소.** 위 '정정 2' 참고.

`.env`는 있고, Workers 서버도 배포돼 동작 중이다. 실제 문제는 **OpenAI 키 하나**다.

`GOOGLE_PLACES_KEY`(클라이언트)만 비어 있는데, 이건 해외 좌표 검색 폴백에만 쓰인다.
국내에서는 카카오 로컬이 담당하므로 데모에는 영향이 없다.

**Apple 심사 사유가 아니다.** 대신 ⑤와 묶여 데모의 핵심 가치를 막는다.

### ④ 백그라운드 위치 — README가 사실과 다르다 — Guideline 2.5.4

README는 "백그라운드 위치는 요구하지 않아 승인 장벽이 낮습니다"라고 적혀 있다. 코드는 쓴다. 문서만 낡았다.

- `src/lib/backgroundLocation.ts:52` — `requestBackgroundPermissionsAsync`
- 같은 파일 57행 — `startLocationUpdatesAsync`
- `app.json` — `UIBackgroundModes: ["location"]` + `NSLocationAlwaysAndWhenInUseUsageDescription`

Apple은 지속적 백그라운드 위치의 필요성을 반드시 검증한다.
**7일 내 가능** — ①의 데모 진입점 위에서 영상으로 증명한다. 리젝은 아니어도 심사 시간을 늘리는 요인이다.

README를 먼저 고칠 것. 문서와 코드가 어긋난 채로 심사에 내면 설명이 꼬인다.

### ⑤ 앱의 정체성 — 2026-09-15 배선 완료

"한 문장으로 말하면 경유지를 뽑아준다"가 이 앱의 존재 이유인데, 그 경로가 LLM이 아니라
로컬 규칙이었다. `docs/NEXT.md` '나중에'의 *"`/extract`를 앱에 배선"* 항목.

**배선했다.** `src/lib/intentClient.ts` 가 서버를 부르고, 실패 넷(네트워크·429 일일 상한·
502 OpenAI·모양 불일치)을 전부 로컬 목으로 떨군다. 화면은 `source` 만 보고, 목으로
떨어지면 채팅에 *"서버에 닿지 못해 간단한 규칙으로 알아들었어요"* 를 붙인다.

**남은 선행 조건: ②의 OpenAI 키.** 배선은 끝났고 키가 없어 아직 항상 목으로 떨어진다.

### ⑥ 키가 번들에 인라인된다 — 심사 무관, 운영 위험

`app.config.js` 주석에도 명시돼 있다. 카카오 REST 키 · Google Places 키가 앱에서 추출 가능하다.

`docs/NEXT.md` 운영 항목 — *"구글 일일 할당량 40을 유료 전환 직후 반드시 걸 것. 기본값이 75,000/일"*

**제출 조건이 4주 공개 유지다.** 키가 노출된 채 4주 방치는 과금 사고 시나리오다.
스토어를 가든 안 가든 프록시화가 먼저다.

## 파이프라인 실측 — 어디까지가 진짜인가 (2026-09-15)

"키만 넣으면 목이 아니라 실제로 도는가"를 코드로 따라간 결과.

### 채팅 → A5 까지는 목이 없다

| 단계 | 무엇으로 | 상태 |
|---|---|---|
| 채팅 → 의도 추출 | `/extract` → OpenAI | **`OPENAI_API_KEY` 만 넣으면 동작** |
| 의도 → 칩 | `plan.tsx` `APPLY_INTENT` | 동작 |
| 칩 → 요청 조립 | `usePlanRequest` → `planRequest.ts` | 동작 |
| 칩 → 경로상 장소 검색 | 카카오 로컬 (클라이언트 직접 호출) | 동작 — 웹에서도 확인 |
| 후보 보강 | `/enrich` → 구글 Places + 네이버 블로그 | 동작 (서버에 키 있음) |
| 실측 라우팅 | `/route` → 카카오 모빌리티 | 동작 — 25.72분 실측 |
| A5 3안 + 도착 시각 판정 | `flow.state.result` | 동작 |
| A5 매장 교체 (A4 시트) | props 기반 | 동작 |

`runPlan` 이 `searchAlong` 과 `provider.route` 를 실제로 부른다.

### A6 — "목"이 아니라 "확정 전에는 목"이다

> **2026-09-15 정정.** 처음에 "A6 부터는 아직 목"이라고 적었다. 틀렸다.
> `TimelineScreen` 이 `state.dataset` 을 읽는 건 맞지만, A5 확정 시 `APPLY_LIVE` 가
> **그 dataset 을 통째로 교체**한다. `toLegacyPlan` 이 `result.rescore` 로 실측 leg 를
> 전부 만들고(`origin>slot`·`slot>dest`·`slot>slot` 전 쌍), 후보도 A5 교체 시트와
> **같은 함수**(`slotCandidates`)로 낸다 — 화면과 확정본이 다른 목록을 보면 안 되니까.
> `baseId: v.slotId` 라 `computeChain` 의 조회 키와도 맞는다.
> `docs/NEXT.md` 의 "진행중 탭 구간 시간·거리가 목 표 값" 항목은 그 자체가 낡았다
> (같은 항목이 "toLegacyPlan 이 실측 leg 를 넣으면 맞아진다"고 예고해 뒀고, 그 작업이 됐다).

정확히는 **확정을 거치지 않은 상태에서만 목**이다 — 앱 첫 실행의 `datasets[0]`,
또는 개발 메뉴로 목 데이터셋을 직접 띄운 경우. 투표자는 A5 확정을 거쳐 A6 로 가므로
실측을 본다.

**남은 진짜 결함은 값의 출처가 아니라 시각의 일관성이다.**

| 항목 | 내용 |
|---|---|
| 화면별 도착 시각 불일치 | A5 17:52 / 진행중 17:50 / 타임라인 17:49. `NEXT.md` 최상단 '우선' 항목 |
| 확정 시각 재클럭 | `toLegacyPlan` 이 계산 시작 시각을 출발로 고정한다. A5 에 오래 머물면 타임라인이 과거 기준이 된다 |
| 할 일이 비어 있다 | `toLegacyPlan` 이 `tasks: []` 로 만들고, 경유지에 추가 입구도 없다 |

불일치의 기전은 **반올림 지점**으로 보인다. `toLegacyPlan` 이 leg 마다
`Math.round(arrive - clock)` 로 정수화하고, `computeChain` 이 그 정수들을 다시 더한다 —
각 구간을 반올림한 뒤 합한 값은 합을 반올림한 값과 다르다. A5 는 `timing` 을 그대로 쓴다.

**데모 범위 판단**: 투표자 체험(말하고 → 뽑히고 → 도착 시각 → 3안 비교 → 확정)에는
지장이 없다. 다만 A5 와 A6 의 숫자가 1~2분 어긋나 보이는 건 "답 먼저" 원칙을 깬다.

### 고친 누수 — `openNow`·`flexible`

`usePlanRequest` 가 두 값을 하드코딩(`flexible: true, openNow: false`)해서 버리고 있었다.
`runPlan` 은 줄곧 받을 준비가 돼 있었는데(슬롯 조립부) 값이 오지 않았을 뿐이다.
LLM 이 "문 연 약국"에서 `openNow: true` 를 뽑아도 파이프라인에 닿지 못했다.

원인은 `IntentChip` 이 두 필드를 안 들고 있던 것. 타입에 추가하고 두 생성 지점을 배선했다.
**화면 어디에도 드러나지 않는 종류의 결함**이라 매핑을 `planRequest.ts` 순수 함수로 빼고
테스트로 묶었다. `count` 는 칩을 개수만큼 복제하는 방식이라 살아 있었다.

### 웹에서만 걸리는 것 — CORS

브라우저는 preflight 를 보내는데 서버가 `OPTIONS` 를 처리하지 않았다.
**웹 데모에서는 `/extract`·`/route`·`/enrich` 가 전부 막힌다.** 네이티브 앱에는 CORS 가
없어서 여기까지 드러나지 않았다. 카카오 로컬 검색만 웹에서 동작했던 건 그게 서버를
거치지 않는 클라이언트 직접 호출이라서다.

허용 오리진 목록으로 고쳤다(`wrangler.toml` 의 `ALLOWED_ORIGINS`). **배포해야 적용된다.**
